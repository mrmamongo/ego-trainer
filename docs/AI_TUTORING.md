# Учебный ассистент и проверка понимания

Сервер предоставляет подсказки, объяснение кода и обязательную защиту успешного
решения для студентов, которым администратор выдал доступ. Методика адаптирована
из TrainBrain: самостоятельная попытка, короткая коррекция одного пробела,
новый пример после помощи, выводы с конкретными свидетельствами из ответов.

## Настройка

Установи серверные зависимости и примени обычную миграцию:

```powershell
uv sync --extra server --extra dev
uv run ego-server migrate
```

Адреса API, модели, тарифы, лимиты и включение ассистента хранятся в SQLite.
В админке открой **Студенческий AI**. Укажи отдельно основную
модель и маленькую проверяющую модель. Используется OpenAI-совместимый
`POST <base_url>/chat/completions`; адрес должен включать `/v1`, если он нужен
провайдеру. JSON mode можно отключить для API, которое его не поддерживает;
содержимое ответа всё равно должно соответствовать JSON-контракту.

API-ключи зашифрованы Fernet. Используется общий механизм шифрования настроек сервера. Рекомендуется задать стабильный
`EGO_SETTINGS_ENCRYPTION_KEY` в окружении серверного процесса. Генерация:

```powershell
uv run python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

Сохрани этот ключ отдельно от БД и используй при каждом запуске. Если он не задан,
действует существующая политика сервера: ключ выводится из JWT-секрета. Его потеря
требует повторно задать API-ключи моделей. Ключи моделей никогда не возвращаются
клиенту; при чтении конфигурации доступны только признаки `api_key_set`.
PUT конфигурации без поля `api_key` сохраняет существующий ключ, явное пустое
значение очищает его. Серверные путь БД и JWT-секрет остаются bootstrap-настройками
`EGO_DB_PATH`, `EGO_JWT_SECRET` в окружении / `.env`.

В карточке студента включи доступ и обязательную защиту, затем пополни баланс.
Баланс используется как бюджет расходов; поступления через платёжную систему
не реализованы. Тарифы вводятся в USD за миллион входных / выходных токенов
отдельно для каждой модели. Нулевой тариф означает бесплатный вызов.

## Проверка и выдача ответов

Каждый ответ основной модели проходит отдельный запрос к проверяющей модели.
При отказе, ошибке или некорректном формате ответ основной модели не выдаётся
студенту и не сохраняется в видимой истории. Моделям передаются только условие,
код студента и история диалога: эталон и скрытые тесты не передаются.
У ассистента нет инструментов редактирования или выполнения кода.

Обе модели расходуют бюджет, включая отклонённые ответы. Перед запросом сервер
атомарно резервирует консервативную оценку стоимости обеих моделей. После ответа
списываются расходы по `usage`; при отсутствии `usage` используются помеченные
консервативные оценки. Повтор запроса с тем же `request_id` не вызывает моделей
и не списывает деньги повторно. Учёт ведётся целыми миллионными долями USD.
При таймауте/обрыве транспорта расходы помечаются как оценочные, поскольку
провайдер мог выполнить запрос. После аварийного перезапуска незавершённая
резервация через десять минут закрывается консервативным списанием и диалог
разблокируется при следующем чтении аккаунта.

LLM-проверка является дополнительным ограничением выдачи, а не гарантией
отсутствия ошибок модели. Администратор видит историю расходов и свидетельства
проверки понимания.

## Защита решения

Успешный серверный `/check` сохраняет снимок кода, версию задания, условие
и хеш решения. Защита проверяет этот снимок; присланный клиентом другой код
не подменяет сданное решение. Прогресс по тестам и понимание записываются отдельно.
Отправка локального результата через `/progress/push` не создаёт право на защиту.

Последовательность: объяснение механизма → трассировка нового примера → перенос
на близкое изменение условия. Каждый этап требует самостоятельного ответа и
дословного свидетельства из него, подтверждённых проверяющей моделью. Две
неуспешные попытки на этапе завершают защиту с `needs_review`; можно начать
повторную защиту. `confirmed` требует успешного прохождения всех трёх этапов.
Это подтверждение понимания конкретного решения, без оценки общего уровня
студента или заявления о долгосрочном усвоении.

В расширении команда **Ego: Учебный ассистент** открывает диалог для текущего
задания. После успешной серверной проверки требуемая защита открывается
автоматически. При отсутствии доступа или средств показывается причина.

## Учебные пояснения в контенте

Контент остаётся в каноническом репозитории заданий. В Markdown можно добавить
следующие секции; парсер сохраняет их в условии, их видят студент и ассистент:

```markdown
## Учебные цели
- Различать поиск первого совпадения и сбор всех совпадений.

## Пояснения
Первый элемент определяется порядком входного списка. Учти пустой список.

## Проверка понимания
Объясни механизм, предскажи результат на новом входе и адаптируй принцип.
```

Пояснения описывают понятия и ограничения, не раскрывают готовое решение.
Пример расширенного задания находится в монорепозиторном fixture F1.

## HTTP

- `GET /ai/me`: доступ, причина недоступности, остаток и расходы.
- `POST /ai/sessions`: `{task_id, mode, student_code?, submission_id?}`.
- `GET /ai/sessions/{id}`: собственный диалог.
- `POST /ai/sessions/{id}/messages`: `{text, request_id, student_code?}`; пустой `text` запускает защиту.
- `GET /ai/submissions`: собственные результаты защиты.
- `GET /progress/{student_id}/understanding`: результаты и свидетельства для преподавателя или самого студента; доступны также через MCP `get_student_understanding`.
- `GET|PUT /admin/ai/settings`: конфигурация моделей и тарифов.
- `GET|PUT /admin/ai/students/{id}`: доступ и обязательность защиты.
- `POST /admin/ai/students/{id}/credits`: `{amount_usd, request_id}`.
- `GET /admin/ai/students/{id}/usage`: последние 100 записей расходов.
- `GET /admin/ai/students/{id}/submissions`: результаты и свидетельства.

Все `/admin/ai` требуют роль администратора. Личность студента определяется JWT.
Без выданного доступа, настроенных обеих моделей и доступного бюджета вызовы
моделей блокируются на сервере независимо от состояния интерфейса расширения.
