# ADR-0018: Многофайловые челленджи по этапам

**Status:** Accepted (реализация по фазам ниже)
**Date:** 2026-10-29
**Related:** ADR-0016 (каталог Project → Folder → Task), `docs/TESTS_DESIGN.md`, `docs/COURSE_MAP.md`
(пробел 7 «Модули и структура проекта»)

## Context

Все задачи сейчас однофайловые: студент пишет одну функцию `task_*` в `.student.py`, сервер
(`POST /check`) запускает её в подпроцессе (`ego.runner.run_function`) и сравнивает результат с ожидаемым.
Проекты 10–11 — это тоже одна функция или `handle(state, command)`.

Нужна программа из нескольких модулей, которая растёт по этапам, как в CodeCrafters. На каждом этапе
студент дописывает свою папку проекта, а проверка гоняет тесты текущего и всех прошлых этапов.

Решения владельца (2026-10-29): одна папка на челлендж; проверка — импорт модулей плюс «чёрный ящик»
(запуск `main.py` с вводом); сдача через расширение, git push в Forgejo — позже.

## Decision

### D18.1. Челлендж = папка каталога, этап = задача

Папка с `kind: challenge` в `folder.yaml`. Каждый этап — обычная задача каталога (своя строка в `tasks`,
свой прогресс, теория, теги), поэтому кабинет, рекомендации и разбор работают без изменений.

```
folders/kv_store/
  folder.yaml                  # kind: challenge + workspace (ниже)
  lesson_*.md                  # теория, как в обычных папках
  starter/                     # что получает студент в начале: main.py, storage.py, …
  solution/                    # эталон — проект после последнего этапа
  stage_01_parse.md            # условие этапа: frontmatter id/title/order/theory/tags
  stage_01_parse.tests.py      # тесты этапа
  stage_01_parse.solution/     # (необязательно) эталон проекта ровно после этого этапа
  stage_02_set_get.md
  …
```

```yaml
# folder.yaml
id: kv_store
kind: challenge
name: "Своё хранилище ключ-значение"
order: 1
workspace:
  entry: main.py               # что запускает чёрный ящик
  include: ["*.py", "data/*.json"]
  max_files: 20
  max_bytes: 200000
```

У этапа нет `.student.py` и `.solution.py`: код живёт в папке проекта. Хеш версии этапа считается
по условию (`.md`), как и сейчас; тесты не хешируются (`version_policy: declare`).

### D18.2. Проверка этапа N = тесты этапов 1..N

Регрессия как в CodeCrafters: сломал этап 2, доделывая этап 5, — этап 5 не засчитан. Результат
группируется по этапам. В прогресс пишется только этап N (passed, если прошли все 1..N); прогресс
прошлых этапов не трогается.

### D18.3. Тесты: импорт и чёрный ящик

Два декларативных вида в `ego.testing` — в духе `@case`:

```python
from ego.testing import case, program

# Импорт: вызвать функцию модуля из папки студента.
@case(target="commands.parse_command", args=("set a 1",), expected=("SET", ["a", "1"]))
def stage_parse(): ...

# Чёрный ящик: запустить entry с вводом, сравнить вывод.
@program(
    stdin="SET a 1\nGET a\nEXIT\n",
    expected_stdout="OK\n1\n",
    description="SET, потом GET",
    files={"data/store.json": '{"x": "5"}'},          # (необяз.) файлы до запуска
    expect_files={"data/store.json": {"x": "5", "a": "1"}},  # (необяз.) JSON после
)
def stage_repl(): ...
```

- `target="module.func"` вызывает функцию модуля в песочнице. Остальные аргументы `@case` работают как сейчас:
  `level`, `comparison`, `hide_expected`, `check_inputs_unchanged`.
- `@program` запускает `python -S <entry>` в копии папки, `cwd` = эта копия. Вывод сравнивается построчно,
  хвостовые пробелы и последний перевод строки не считаются. `match="exact"|"lines"|"contains"`
  (по умолчанию `lines`). Можно задать `expected_exit=0` и `timeout`.
- `@rules` работают по всем `.py` файлам проекта: `require_functions`, `forbid_imports` и правила классов
  проверяются по проекту целиком, а с `file="storage.py"` — по одному файлу.
- `@before`/`@after` — как сейчас.

### D18.4. Песочница

`ego.runner.run_project(files, …)`: временная папка, файлы раскладываются по относительным путям, запуск
`python -S` с `cwd` = папка; в импорт-режиме обёртка кладёт папку первой в `sys.path` и делает
`importlib.import_module`. Модуль запускается под своим именем, поэтому блок `if __name__ == "__main__"`
в импорт-режиме не срабатывает. Мягкие предупреждения `BLOCKED_IMPORTS` — как сейчас. Работа с файлами
разрешена внутри временной папки; это best-effort, как и остальная песочница MVP.

Пути проверяются до записи: только относительные POSIX-пути, без `..`, без абсолютных и без
`.cogito/`, `__pycache__/`, `.venv/`; файл должен подходить под `include`; соблюдаются `max_files` и `max_bytes`.

### D18.5. API

- `POST /check`: новое поле `files: dict[str, str]`. В запросе ровно одно из `student_code`/`files`.
  Для этапа челленджа принимаются только `files`, для обычной задачи — только `student_code`.
  Ответ — прежний `CheckResponse`, у каждого результата есть `stage` (номер этапа) и `stage_title`.
- `GET /challenges/<folder_id>`: метаданные, `workspace`, список этапов (id, title, order, статус ученика)
  и стартовые файлы `starter` (`{path: content}`).
- Журнал запусков хранит файлы целиком (`runs.files_json`, аддитивная миграция). Для AI и истории
  есть склейка `# === path ===\n<content>`.

### D18.6. Расширение

- «Начать челлендж»: папка `<рабочая папка Cogito>/challenges/<folder_id>/`, стартовые файлы и
  `.cogito/challenge.json` (`{id, server, stage}`). Существующие файлы **никогда** не перезаписываются.
- Панель этапа показывает условие текущего этапа и список этапов со статусами. Все этапы открыты
  (мягко, без блокировки), следующий подсвечен.
- «Проверить этап» собирает файлы по `include` с учётом лимитов, отправляет `files`, показывает
  результаты по этапам. Если этап пройден, панель предлагает открыть следующий.
- «Запустить» открывает терминал с `python main.py` в папке проекта, чтобы поиграть с программой руками.

### D18.7. Проверка контента

`scripts/verify_challenges.py`: эталон `solution/` проходит все этапы; `starter/` не проходит этап 1;
если есть `stage_K.solution/`, он проходит этапы 1..K и не проходит K+1; на каждом этапе
не меньше трёх smoke-проверок; все пути и `include` корректны.

## Фазы

1. **Ядро и сервер:** формат и парсер (`ego/content_repo.py`, `ego/catalog.py`), `@program` и `target=`,
   `run_project`, проверка по этапам, `POST /check` с `files`, `GET /challenges/<id>`, миграция, верификатор,
   крошечный челлендж-фикстура на два этапа для тестов, `docs/TESTS_DESIGN.md`.
2. **Расширение:** D18.6.
3. **Контент:** первый челлендж «Своё хранилище ключ-значение» (проект `challenges`, после папки 13
   курса «Python с нуля»): разбор команды → SET/GET → DEL/EXISTS/KEYS → цикл `main.py` → ошибки с кодами →
   INCR/DECR → сохранение в JSON → транзакции.
4. **Позже:** сдача через git push в Forgejo (репозиторий на челлендж, webhook → проверка).

## Consequences

- Обычные задачи не меняются; поле `student_code` остаётся.
- Этапы — обычные задачи, поэтому прогресс, кабинет и рекомендации их видят сразу; разбор по типам
  считает их по тегам, как и раньше.
- Старое расширение не знает про `files`. Для этапа челленджа оно получит 422 с понятным текстом
  «обнови Cogito».
