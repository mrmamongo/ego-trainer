# Задача PR15: Профиль с проверкой адреса

## Условие

### Как это работает

Сеттер может не только проверить значение, но и **привести его к нужному виду** перед записью. Тогда в объекте всегда лежит чистое значение, а остальной код не думает про пробелы и регистр.

```python
class Tag:
    def __init__(self, text):
        self.text = text

    @property
    def text(self):
        return self._text

    @text.setter
    def text(self, value):
        value = value.strip().lower()          # привели к виду
        if value == "":
            raise ValueError("тег пустой")     # проверили
        self._text = value                     # запомнили чистое

    @property
    def hashtag(self):                         # только чтение, считается из _text
        return "#" + self._text
```

| Действие | Результат |
|---|---|
| `["new", "  Python "]` | `"ok"` |
| `["get", "text"]` | `"python"` |
| `["get", "hashtag"]` | `"#python"` |
| `["set", "text", " "]` | `["error", "ValueError", "тег пустой"]` |
| `["get", "text"]` | `"python"` |

Проверка идёт **после** очистки: строка из одних пробелов становится пустой.

### Задание

Напиши класс `Profile`:

- `__init__(name, email)`: `name` хранится как обычный атрибут, `email` записывается **через свойство**;
- свойство `email` (чтение и запись): сеттер убирает пробелы по краям и приводит адрес к нижнему регистру (`strip()` и `lower()`), потом проверяет: адрес должен содержать `@`, но не в самом начале и не в самом конце, иначе `ValueError("некорректный email")`; хранится в `_email`;
- свойство `username` только для чтения: часть адреса до `@`.

## Аргументы

- `actions` — список действий сценария. Его подаёт проверка, ты его не пишешь. Как читать сценарий, объяснено в карточке «Как читать сценарий».

## Возвращает

Список результатов: по одному на каждое действие сценария, в том же порядке. Функция-рамка в конце файла уже готова.

## Правила

- Пиши только класс `Profile`; рамку внизу файла не трогай.
- Снаружи класса к `_email` обращаться нельзя.
- Сначала очисти адрес, потом проверяй и записывай.
- Текст ошибки должен совпасть с условием слово в слово.

## Пример

| Действие | Результат |
|---|---|
| `["new", "Аня", "  Anya@Mail.ru "]` | `"ok"` |
| `["get", "email"]` | `"anya@mail.ru"` |
| `["get", "username"]` | `"anya"` |
| `["set", "email", "anya"]` | `["error", "ValueError", "некорректный email"]` |
| `["get", "email"]` | `"anya@mail.ru"` |

## Учебные цели

- Привести значение к нужному виду в сеттере и только потом проверить.
- Сделать производное свойство (`username`), которое обновляется вместе с адресом.
- Сохранить правильное значение, если новое отклонено.

## Проверка понимания

Что станет с `username`, если присвоить новый `email`? Почему пустая строка из пробелов отклоняется, хотя в ней нет слова «пусто»?
