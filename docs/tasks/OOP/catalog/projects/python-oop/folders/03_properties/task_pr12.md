# Задача PR12: Бонус в обход проверки

## Условие

### Как это работает

Сеттер охраняет правило, только если все пишут через **свойство**. Запись прямо в `_balance` снаружи класса проверку обходит, и объект становится некорректным:

```python
acc.balance = acc.balance - 500     # верно: сеттер проверит и откажет
acc._balance = acc._balance - 500   # неверно: проверку никто не вызвал
```

Исправить обход легко: заменить `acc._balance` на `acc.balance`. А чтобы функция сообщила, получилось ли изменение, присваивание кладут в `try`: если сеттер бросил `ValueError`, функция возвращает `False`.

```python
def try_set(gauge, value):
    try:
        gauge.level = value
    except ValueError:
        return False
    return True
```

| Вызов | Результат | Пояснение |
|---|---|---|
| `try_set(gauge, 5)` | `True` | сеттер принял |
| `try_set(gauge, -1)` | `False` | сеттер отказал, `level` не изменился |

### Задание

Класс `Account` готов: у него есть свойство `balance` с проверкой. Функция `apply_change(account, delta)` должна прибавить к балансу `delta` (оно может быть отрицательным) и вернуть `True`. Если баланс ушёл бы в минус, баланс остаётся прежним, а функция возвращает `False`. Сейчас функция пишет прямо в `_balance` и обходит проверку. Исправь её.

## Аргументы

- `start` — стартовый баланс, неотрицательное целое число.
- `deltas` — список целых чисел: что по очереди прибавляют к балансу (могут быть отрицательными, список может быть пустым).

## Возвращает

Словарь с двумя ключами: `"results"` — список `True`/`False` по одному на каждое изменение, и `"balance"` — баланс в конце.

## Правила

- Меняй только функцию `apply_change`; класс `Account` и рамку не трогай.
- Не пиши `account._balance` снаружи класса: работай через `account.balance`.
- Функция возвращает `True` или `False`, а не бросает ошибку наружу.

## Пример

```python
task_pr12_change(100, [-30, -100, 50])
# -> {"results": [True, False, True], "balance": 120}
task_pr12_change(5, [])
# -> {"results": [], "balance": 5}
```

## Учебные цели

- Узнавать обход проверки: запись в `_поле` снаружи класса.
- Работать с объектом через свойство и ловить `ValueError` от сеттера.
- Видеть, что правило в сеттере защищает только тогда, когда им пользуются все.

## Проверка понимания

Какой баланс получится после `[-30, -100, 50]` из `100`, если оставить запись в `_balance`? Почему функция не проверяет баланс сама, а доверяет сеттеру?
