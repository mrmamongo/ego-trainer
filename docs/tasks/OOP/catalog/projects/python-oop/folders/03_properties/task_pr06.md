# Задача PR06: Сеттер, который вызывает сам себя

## Условие

### Как это работает

Сеттер вызывается каждый раз, когда пишут `acc.balance = ...`. Если **внутри** сеттера снова написать `self.balance = value`, это тоже присваивание свойству, и сеттер вызывает сам себя, потом ещё раз, и ещё. Python останавливает такую бесконечную цепочку ошибкой `RecursionError`.

```python
class Box:
    @property
    def size(self):
        return self._size

    @size.setter
    def size(self, value):
        self.size = value        # снова вызывает этот же сеттер: RecursionError
```

Хранить значение нужно в «складе» `_size`, а свойство `size` — это только вход.

В сценарии такая ошибка не обрывает проверку, а записывается как результат:

| Действие | Результат |
|---|---|
| `["new", "Аня", 100]` | `"ok"` |
| `["set", "balance", 50]` | сейчас `["error", "RecursionError", ...]`, а должно быть `"ok"` |
| `["get", "balance"]` | должно быть `50` |

### Задание

В классе `BankAccount` баланс — свойство. Сеттер отклоняет отрицательные значения, но на нормальные значения почему-то падает. Найди ошибку и исправь. Методы `deposit` и `withdraw` пишут баланс через свойство, их менять не нужно.

## Аргументы

- `actions` — список действий сценария. Его подаёт проверка, ты его не пишешь. Как читать сценарий, объяснено в карточке «Как читать сценарий».

## Возвращает

Список результатов: по одному на каждое действие сценария, в том же порядке. Функция-рамка в конце файла уже готова.

## Правила

- Меняй только одну строку в сеттере; рамку внизу файла не трогай.
- Проверку отрицательного значения и текст ошибки оставь как есть.
- Баланс по-прежнему читается и пишется как `acc.balance`.

## Пример

| Действие | Результат |
|---|---|
| `["new", "Аня", 100]` | `"ok"` |
| `["set", "balance", 50]` | `"ok"` |
| `["get", "balance"]` | `50` |
| `["set", "balance", -1]` | `["error", "ValueError", "баланс не может быть отрицательным"]` |

## Учебные цели

- Узнавать `RecursionError` в сеттере: свойство пишет само в себя.
- Хранить значение в `_имя`, а проверку держать в сеттере.
- Видеть, что `deposit` и `withdraw` получают проверку через свойство «даром».

## Проверка понимания

Почему отрицательный баланс отклонялся правильно, а нормальный — нет? Что произойдёт при `withdraw` больше баланса в исправленном классе и откуда возьмётся текст ошибки?
