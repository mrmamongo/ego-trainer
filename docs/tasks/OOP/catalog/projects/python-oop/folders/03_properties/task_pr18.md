# Задача PR18: Полоса прогресса без устаревания

## Условие

### Как это работает

Сейчас `percent` и `bar` — обычные атрибуты, а полоса `bar` собирается в двух местах:

```python
class ProgressBar:                                                          # 1
    def __init__(self, percent):                                            # 2
        self.percent = percent                                              # 3
        self.bar = "#" * (percent // 10) + "." * (10 - percent // 10)        # 4
    def advance(self, step):                                                # 5
        self.percent = min(100, self.percent + step)                        # 6
        self.bar = "#" * (self.percent // 10) + "." * (10 - self.percent // 10)  # 7
```

**Где реализовано старое правило:** строка 4 строит полосу при создании, строка 7 — после шага, строка 6 не даёт процентам превысить `100`.

**Что меняется:** `bar` перестаёт быть полем и становится свойством только для чтения, которое каждый раз считается из `percent`. Полоса больше не устаревает, если `percent` присвоили напрямую. А `percent` становится свойством с сеттером: значения вне `0..100` отклоняются через `ValueError("процент от 0 до 100")`, в том числе при создании.

**Что нельзя трогать:** формат полосы (десять клеток: `#` за каждые полные 10 процентов, остальные `.`) и то, что `advance` не поднимает процент выше `100`.

| Действие | Было | Стало |
|---|---|---|
| `["set", "percent", 80]` при `percent=30`, затем `["get", "bar"]` | `"###......."` (устарела) | `"########.."` |
| `["new", 150]` | `"ok"` | `["error", "ValueError", "процент от 0 до 100"]` |
| `["advance", -50]` при `percent=30` | `None`, `percent=-20` | `["error", "ValueError", "процент от 0 до 100"]` |

### Задание

Раньше `bar` строился отдельно и мог устареть. Теперь `bar` — свойство только для чтения, которое считается из `percent`, а `percent` — свойство с проверкой. Метод `advance` остаётся и работает как раньше: добавляет `step`, но не выше `100`. Измени готовый класс.

## Аргументы

- `actions` — список действий сценария. Его подаёт проверка, ты его не пишешь. Как читать сценарий, объяснено в карточке «Как читать сценарий».

## Возвращает

Список результатов: по одному на каждое действие сценария, в том же порядке. Функция-рамка в конце файла уже готова.

## Правила

- Не переписывай класс с нуля: замени поля свойствами.
- Полосу `bar` нигде не храни, она только считается.
- Рамку внизу файла не трогай.
- Текст ошибки должен совпасть с условием слово в слово.

## Пример

| Действие | Результат |
|---|---|
| `["new", 30]` | `"ok"` |
| `["set", "percent", 80]` | `"ok"` |
| `["get", "bar"]` | `"########.."` |
| `["advance", 50]` | `None` |
| `["get", "percent"]` | `100` |
| `["set", "bar", "x"]` | `["error", "AttributeError", ""]` |

## Учебные цели

- Заменить производное поле вычисляемым свойством, чтобы оно не устаревало.
- Добавить проверку в сеттер, не ломая метод `advance`.
- Сохранить старый формат полосы и границу в 100 процентов.

## Проверка понимания

Почему раньше `bar` мог не совпасть с `percent`, а теперь не может? Что будет с `advance(-50)`, если процент равен `30`?
