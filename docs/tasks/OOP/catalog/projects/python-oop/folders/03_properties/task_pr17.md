# Задача PR17: Баланс с защитой

## Условие

### Как это работает

Сейчас баланс — обычный атрибут. Правило «не в минус» знает только `withdraw`:

```python
class BankAccount:                                       # 1
    def __init__(self, owner, balance):                  # 2
        self.owner = owner                               # 3
        self.balance = balance                           # 4
    def deposit(self, amount):                           # 5
        self.balance = self.balance + amount             # 6
    def withdraw(self, amount):                          # 7
        if amount > self.balance:                        # 8
            raise ValueError("недостаточно денег")       # 9
        self.balance = self.balance - amount             # 10
```

**Где реализовано старое правило:** в строках 8–9, и только в `withdraw`. Остальные пути обходят его: `BankAccount("Аня", -5)` создаётся, `acc.balance = -5` проходит, `deposit(-500)` уводит баланс в минус.

**Что меняется:** `balance` становится свойством. Проверку «не меньше нуля» переносят в сеттер, значение хранится в `_balance`, а `__init__` записывает баланс **через свойство**. Тогда правило действует везде.

**Что нельзя трогать:** метод `withdraw` по-прежнему первым делом сообщает `ValueError("недостаточно денег")`, `deposit` и атрибут `owner` работают как раньше.

| Действие | Было | Стало |
|---|---|---|
| `["new", "Аня", -1]` | `"ok"` | `["error", "ValueError", "баланс не может быть отрицательным"]` |
| `["set", "balance", -5]` | `"ok"` | `["error", "ValueError", "баланс не может быть отрицательным"]` |
| `["withdraw", 500]` при балансе `20` | `["error", "ValueError", "недостаточно денег"]` | то же самое |

### Задание

Раньше баланс был обычным атрибутом, и правило «не меньше нуля» проверял только `withdraw`. Теперь баланс — свойство с сеттером: отрицательное значение отклоняется через `ValueError("баланс не может быть отрицательным")` при создании, при присваивании и в любом методе. Старое поведение `withdraw` и `deposit` остаётся. Измени готовый класс.

## Аргументы

- `actions` — список действий сценария. Его подаёт проверка, ты его не пишешь. Как читать сценарий, объяснено в карточке «Как читать сценарий».

## Возвращает

Список результатов: по одному на каждое действие сценария, в том же порядке. Функция-рамка в конце файла уже готова.

## Правила

- Не переписывай класс с нуля: превращай `balance` в свойство.
- Снаружи класса к `_balance` обращаться нельзя.
- Сообщение `"недостаточно денег"` из `withdraw` остаётся прежним.
- Рамку внизу файла не трогай.

## Пример

| Действие | Результат |
|---|---|
| `["new", "Аня", 100]` | `"ok"` |
| `["deposit", 50]` | `None` |
| `["set", "balance", -5]` | `["error", "ValueError", "баланс не может быть отрицательным"]` |
| `["withdraw", 500]` | `["error", "ValueError", "недостаточно денег"]` |
| `["get", "balance"]` | `150` |

## Учебные цели

- Превратить обычный атрибут в свойство с проверкой, не ломая старые вызовы.
- Перенести правило из одного метода в сеттер, чтобы оно действовало везде.
- Сохранить прежнее поведение метода (`withdraw` с его сообщением).
