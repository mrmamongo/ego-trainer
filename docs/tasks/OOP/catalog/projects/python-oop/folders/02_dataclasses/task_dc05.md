# Задача DC05: Склад не находит свой товар

## Условие

### Как это работает

Обычный класс сравнивает объекты так же, как `is`: два объекта с одинаковыми полями считаются разными. Поэтому `in` по списку таких объектов ничего не находит:

```python
class Coin:
    def __init__(self, value):
        self.value = value

Coin(5) == Coin(5)          # False: это два разных объекта
Coin(5) in [Coin(5)]        # False
```

У dataclass `==` сравнивает поля, и тот же код работает:

```python
@dataclass
class Coin:
    value: int

Coin(5) == Coin(5)          # True
Coin(5) in [Coin(5)]        # True
```

| Класс | `Coin(5) in [Coin(5)]` |
|---|---|
| обычный, свой `__init__` | `False` |
| с `@dataclass` | `True` |

### Задание

Функция `task_dc05_has_item(stock, name, qty)` должна ответить, есть ли на складе запись `Item(name, qty)`. Но она всегда возвращает `False`: `Item` написан как обычный класс. Исправь класс `Item`, чтобы записи с равными полями считались равными.

## Аргументы

- `stock` — список пар `[название, количество]` (может быть пустым).
- `name` — название товара, строка.
- `qty` — количество, целое число.

## Возвращает

`True`, если в `stock` есть пара с этим названием **и** этим количеством, иначе `False`.

## Правила

- Исправляй класс `Item`; в функции ничего менять не нужно.
- Класс `Item` должен стать dataclass с полями `name` и `qty`.
- Список `stock` менять нельзя.

## Пример

```python
task_dc05_has_item([["Меч", 3], ["Щит", 1]], "Щит", 1)   # -> True
task_dc05_has_item([["Меч", 3], ["Щит", 1]], "Щит", 2)   # -> False
task_dc05_has_item([], "Меч", 1)                         # -> False
```

## Учебные цели

- Объяснять, почему у обычного класса `==` не сравнивает поля.
- Заменять ручной `__init__` на `@dataclass` с объявленными полями.
- Видеть, что `in` для списка опирается на `==`.
