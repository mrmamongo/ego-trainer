# Задача DC04: Реакции склеились в одно сообщение

## Условие

### Как это работает

Помнишь ловушку из «Python с нуля»: значение по умолчанию вычисляется один раз, поэтому список `items=[]` в функции становится общим для всех вызовов. В dataclass тот же приём не просто опасен, а запрещён: Python остановит программу при создании класса.

```python
@dataclass
class Quest:
    title: str
    tags: list = []          # ValueError: mutable default <class 'list'> for field tags is not allowed
```

Исправляют так: вместо готового списка передают **функцию**, которая создаёт новый список для каждого объекта:

```python
from dataclasses import dataclass, field

@dataclass
class Quest:
    title: str
    tags: list = field(default_factory=list)
```

| Запись поля | Что происходит |
|---|---|
| `tags: list = []` | класс не создаётся, `ValueError` |
| `tags: list = field(default_factory=list)` | у каждого `Quest` свой пустой список |

### Задание

Класс `ChatMessage` хранит автора, текст и реакции под сообщением. Сейчас файл падает ещё до запуска сценария: поле `reactions` объявлено с общим списком по умолчанию. Исправь только объявление этого поля, чтобы у каждого сообщения были свои реакции.

Пример сценария (действие → результат):

| Действие | Результат |
|---|---|
| `["new", "Аня", "привет"]` | `"ok"` |
| `["react", "ок"]` | `1` |
| `["new", "Боря", "пока"]` | `"ok"` |
| `["get", "reactions"]` | `[]` |

## Аргументы

- `actions` — список действий сценария. Первое действие — `["new", ...]`: создать объект класса `ChatMessage` с этими аргументами. Дальше: `["get", "поле"]` прочитать поле, `["set", "поле", значение]` записать поле, `["имя_метода", аргументы...]` вызвать метод.

## Возвращает

Список результатов, по одному на действие: `"ok"` для `new` и `set`, значение поля для `get`, то, что вернул метод. Если действие бросило ошибку, результат такой: `["error", "ИмяОшибки", "сообщение"]`. Объект вместо значения превращается в имя его класса.

## Правила

- Пиши только класс выше строки «Ниже ничего не меняй». Рамку (`def task_...` и `given_...`) не трогай: она создаёт объект и выполняет сценарий.
- Методы должны **возвращать** значения, а не печатать их.
- Класс должен остаться dataclass, метод `react` оставь как есть.

## Пример

```python
task_dc04_message([["new", "Аня", "привет"], ["react", "ок"], ["react", "огонь"]])   # -> ["ok", 1, 2]
task_dc04_message([["new", "Боря", "пока"], ["get", "reactions"]])                 # -> ["ok", []]
```

## Учебные цели

- Узнавать ошибку «mutable default» при объявлении dataclass.
- Заменять изменяемое значение по умолчанию на `field(default_factory=...)`.
- Понимать, зачем каждому объекту нужен свой список.

## Проверка понимания

Что вернёт `ChatMessage('А', 'б').reactions` в исправленном классе? Почему нельзя написать `field(default_factory=list())`?
