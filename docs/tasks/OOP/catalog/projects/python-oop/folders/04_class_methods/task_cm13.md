# Задача CM13: Повторить один раз

## Условие

### Как это работает

Обёртка может поймать ошибку исходной функции и решить, что делать дальше. Попытку и повтор записывают как обычный `try`/`except` внутри обёртки:

```python
def safe_or_zero(func):
    def wrapper(*args):
        try:
            return func(*args)
        except ValueError:
            return 0
    return wrapper
```

| Вызов исходной функции | Что вернёт обёртка |
|---|---|
| прошёл без ошибок | её результат |
| бросил `ValueError` | `0`: ошибку обёртка поймала |

Вторая попытка — обычный повторный вызов. Если она тоже упадёт, исключение ничем не ловится и уходит наружу.

### Задание

Напиши декоратор `retry_once(func)`: обёртка вызывает `func`; если та бросила `ValueError`, вызывает её ещё **один** раз и возвращает результат второй попытки. Если и вторая попытка бросила `ValueError`, ошибка не ловится и уходит наружу. Других попыток быть не должно. Рамка подсовывает ненадёжную функцию, которая первые `fail_times` раз бросает `ValueError("сбой")`, и считает, сколько раз её вызвали.

## Аргументы

- `fail_times` — сколько первых вызовов ненадёжной функции бросят ошибку, целое число от 0.

## Возвращает

Список из двух элементов: результат (строка `"готово"` либо `["error", "ValueError", "сбой"]`, если ошибка ушла наружу) и число вызовов ненадёжной функции.

## Правила

- Пиши только декоратор `retry_once` выше строки «Ниже ничего не меняй». Рамку не трогай.
- Ловить нужно только `ValueError`.
- Обёртка принимает любые аргументы (`*args`).

## Пример

```python
task_cm13_retry(0)   # -> ["готово", 1]
task_cm13_retry(1)   # -> ["готово", 2]
task_cm13_retry(2)   # -> [["error", "ValueError", "сбой"], 2]
```

## Учебные цели

- Поймать ошибку внутри обёртки.
- Повторить вызов исходной функции ограниченное число раз.

## Проверка понимания

Сколько раз вызовут функцию при `fail_times`, равном `10`? Почему вторую попытку не нужно оборачивать в `try`?
