# Задача CM07: Метки у всех квестов общие

## Условие

### Как это работает

Список, записанный в теле класса, создаётся **один раз** и принадлежит классу. Все объекты читают один и тот же список, а `append` меняет его для всех сразу. Это та же ловушка, что список по умолчанию в функции.

```python
class Bag:
    items = []                     # один список на все сумки
    def put(self, x):
        self.items.append(x)

a = Bag()
b = Bag()
a.put("меч")
# b.items тоже ["меч"]: это тот же список
```

Личный список создают в `__init__`: `self.items = []`.

### Задание

У квеста есть название `title` и метки `tags`. Метод `add_tag(tag)` добавляет метку **этому** квесту. Сейчас метки одного квеста появляются у всех остальных. Найди ошибку и исправь класс `Quest`.

## Аргументы

- `actions` — список действий сценария. Его подаёт проверка, ты его не пишешь. Как читать сценарий, объяснено в карточке «Как читать сценарий».

## Возвращает

Список результатов: по одному на каждое действие сценария, в том же порядке. Функция-рамка в конце файла уже готова.

## Правила

- Исправь только класс `Quest`; рамку внизу файла не трогай.
- У каждого нового квеста должен быть свой пустой список `tags`.
- Нужны методы `__init__` и `add_tag`.

## Пример

| Действие | Результат |
|---|---|
| `["new", "Волки"]` | `"ok"` |
| `["add_tag", "бой"]` | `None` |
| `["new", "Лис"]` | `"ok"` |
| `["get", "tags"]` | `[]` |

## Учебные цели

- Узнавать общий изменяемый атрибут класса.
- Переносить создание списка в `__init__`, чтобы он был у каждого объекта свой.

## Проверка понимания

Почему ошибка не видна, пока создан только один квест? Что произойдёт, если вместо `self.tags.append(tag)` написать `self.tags = self.tags + [tag]`?
