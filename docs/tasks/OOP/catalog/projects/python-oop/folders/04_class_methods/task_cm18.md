# Задача CM18: Счётчик вызовов в журнале

## Условие

### Как это работает

Сейчас декоратор ведёт журнал результатов:

```python
def announce(func):                          # 1
    def wrapper(*args):                      # 2
        result = func(*args)                 # 3
        wrapper.log.append(result)           # 4
        return result                        # 5
    wrapper.log = []                         # 6
    return wrapper                           # 7
```

**Где реализовано старое правило:** в строках 3–6. Результат каждого вызова дописывается в `wrapper.log`, начальный пустой список создаётся один раз в строке 6.

**Что меняется:** к журналу добавляется счётчик вызовов `wrapper.calls`. Он начинается с `0` (рядом с `wrapper.log = []`) и растёт на единицу при каждом вызове обёртки.

**Что нельзя трогать:** журнал и то, что обёртка возвращает результат исходной функции.

### Задание

Раньше декоратор `announce` только вёл журнал результатов `wrapper.log`. Теперь он должен ещё и считать вызовы в `wrapper.calls`. Измени готовый декоратор.

## Аргументы

- `amounts` — список добавок к здоровью (целые числа), может быть пустым. Рамка применяет `announce` к готовой функции `given_heal(hp, amount)` и вызывает её как `heal(10, amount)` для каждой добавки.

## Возвращает

Список из трёх элементов: ответы обёртки, содержимое `wrapper.log` и значение `wrapper.calls`.

## Правила

- Не переписывай декоратор с нуля: добавь счётчик к готовому.
- Журнал `wrapper.log` и результат вызова остаются как раньше.
- Рамку внизу файла не трогай.

## Пример

```python
task_cm18_calls([1, 2, 3])   # -> [[11, 12, 13], [11, 12, 13], 3]
task_cm18_calls([])          # -> [[], [], 0]
```

## Учебные цели

- Добавить к существующей обёртке второй атрибут состояния.
- Не сломать прежний журнал и возвращаемый результат.

## Проверка понимания

Чему равен `wrapper.calls` до первого вызова? Что изменится, если увеличивать счётчик после вызова исходной функции, а она бросит ошибку?
