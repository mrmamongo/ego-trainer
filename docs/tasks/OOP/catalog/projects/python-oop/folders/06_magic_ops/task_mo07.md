# Задача MO07: Инвентарь никого не находит

## Условие

### Как это работает

Выражение `name in obj` вызывает `obj.__contains__(name)`, и этот метод должен **вернуть** `True` или `False`. Если забыть `return`, метод вернёт `None`, а `in` превратит `None` в `False`:

```python
class Bag:
    def __init__(self, things):
        self.things = things

    def __contains__(self, name):
        name in self.things            # посчитали и выбросили результат

"меч" in Bag(["меч"])                  # False, хотя меч лежит в сумке
```

| Что проверили | Результат |
|---|---|
| `"меч" in Bag(["меч"])` | `False` из-за отсутствия `return` |

Исправление: добавить `return`.

### Задание

В инвентаре предмет считается «есть», если его количество больше нуля. Но проверка `name in inventory` всегда отвечает «нет». Найди ошибку и исправь.

## Аргументы

- `items` — словарь `{название: количество}` (может быть пустым).
- `names` — список названий, которые нужно проверить (может быть пустым).

## Возвращает

Список `True`/`False` по одному на название из `names`.

## Правила

- Исправь только метод `__contains__`; рамку внизу файла не трогай.
- Предмет с количеством `0` считается отсутствующим.

## Пример

```python
task_mo07_has({"меч": 1, "зелье": 0}, ["меч", "зелье", "лук"])   # -> [True, False, False]
task_mo07_has({}, ["меч"])                                         # -> [False]
```

## Учебные цели

- Узнавать ошибку «метод посчитал, но не вернул».
- Помнить, что `in` берёт ответ из `__contains__`.

## Проверка понимания

Что вернёт `__contains__` в исходном классе? Почему `in` при этом не падает, а просто отвечает «нет»?
