# Задача PT05: Журнал квестов пуст со второго раза

## Условие

### Как это работает

Если `__iter__` возвращает `self`, позицию обхода хранит сам объект. После первого `for` он дошёл до конца и больше ничего не отдаст:

```python
class Box:
    def __init__(self, items):
        self.items = items
        self.pos = 0

    def __iter__(self):
        return self

    def __next__(self):
        if self.pos >= len(self.items):
            raise StopIteration
        item = self.items[self.pos]
        self.pos += 1
        return item

box = Box([1, 2])
list(box)          # [1, 2]
list(box)          # []: self.pos так и остался на конце
```

| Вызов | Результат | Почему |
|---|---|---|
| `list(box)` первый раз | `[1, 2]` | позиция шла от нуля |
| `list(box)` второй раз | `[]` | `self.pos` уже равен длине |

Коллекции нужен `__iter__`, который при каждом обходе отдаёт **новый** итератор, например `iter(self.items)`.

### Задание

Журнал `QuestLog` хранит названия квестов. Первый `list(log)` работает, а второй возвращает пустой список. Найди ошибку и исправь класс так, чтобы по журналу можно было ходить сколько угодно раз.

## Аргументы

- `titles` — список названий квестов (строки), список может быть пустым.

## Возвращает

Список из двух списков: названия квестов при первом обходе и при втором. В правильном решении они одинаковые.

## Правила

- Менять нужно только класс `QuestLog`, рамку внизу файла не трогай.
- Класс должен остаться и сохранить методы `add` и `__iter__`.
- Порядок квестов не меняется.

## Пример

```python
task_pt05_quests(['Найти меч', 'Убить дракона'])   # -> [['Найти меч', 'Убить дракона'], ['Найти меч', 'Убить дракона']]
task_pt05_quests(['Собрать грибы'])   # -> [['Собрать грибы'], ['Собрать грибы']]
```

## Учебные цели

- Узнавать ошибку «`__iter__` возвращает `self`» по пустому второму обходу.
- Делать `__iter__`, который отдаёт свежий итератор на каждый обход.

## Проверка понимания

Как поведёт себя исправленный класс, если квест добавить между двумя обходами? Почему тут не нужен метод `__next__`?
