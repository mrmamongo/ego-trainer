# Задача PT07: Транзакция, которая прячет ошибку

## Условие

### Как это работает

Метод `__exit__` решает, что делать с ошибкой из блока `with`. Если он вернул `True`, ошибка подавлена: снаружи её уже не поймать. Если `False` (или ничего), ошибка летит дальше.

```python
class Quiet:
    def __enter__(self):
        return self

    def __exit__(self, exc_type, exc, tb):
        return True

try:
    with Quiet():
        raise ValueError("сбой")
    print("дошли")                 # напечатается
except ValueError:
    print("поймали")               # не напечатается
```

| `__exit__` вернул | `except` снаружи | Строка после `with` |
|---|---|---|
| `True` | не срабатывает | выполняется |
| `False` | срабатывает | пропускается |

### Задание

Класс `Transaction` должен откатывать баланс кошелька, если внутри `with` произошла ошибка, **но не прятать её**: вызывающий код должен узнать о сбое. Сейчас баланс откатывается, а ошибка пропадает. Исправь `__exit__`.

## Аргументы

- `balance` — начальный баланс кошелька (целое число).
- `spends` — список трат (целые числа); трата больше текущего баланса вызывает ошибку `ValueError` внутри `with`.

## Возвращает

Список из двух значений: баланс кошелька после блока и `True`, если ошибка дошла до вызывающего кода, иначе `False`.

## Правила

- Менять нужно только класс `Transaction`, кошелёк `GivenWallet` и рамку внизу файла не трогай.
- При ошибке баланс возвращается к тому, каким был на входе.
- Ошибка не подавляется.

## Пример

```python
task_pt07_run(100, [30, 20])   # -> [50, False]
task_pt07_run(100, [30, 90])   # -> [100, True]
```

## Учебные цели

- Узнавать «`return True` в `__exit__`» как причину молчаливых ошибок.
- Помнить, что откат и пропуск ошибки — две разные вещи.
