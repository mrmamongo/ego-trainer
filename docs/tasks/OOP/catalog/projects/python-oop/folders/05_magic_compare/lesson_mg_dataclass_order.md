# `dataclass(order=True)` и `field(compare=False)`

Всё, что мы писали руками (`__eq__`, `__lt__`, второй критерий кортежем), dataclass умеет делать сам. Достаточно попросить:

```python
from dataclasses import dataclass, field

@dataclass(order=True)
class Run:
    seconds: int
    name: str
    note: str = field(default="", compare=False)
```

`order=True` добавляет `<`, `<=`, `>`, `>=`. Сравниваются не отдельные поля, а **кортеж полей в том порядке, в каком они записаны в классе**: сначала `seconds`, при равенстве `name`, и так далее. Это ровно тот кортеж, который мы собирали в `__lt__`.

```python
a = Run(60, "Аня")                       # 1
b = Run(60, "Боря", "рекорд")            # 2
c = Run(55, "Вика")                      # 3
```

| Выражение | Результат | Почему |
|---|---|---|
| `c < a` | `True` | `55 < 60`, первое поле решило |
| `a < b` | `True` | секунды равны, `"Аня" < "Боря"` |
| `[r.name for r in sorted([b, a, c])]` | `["Вика", "Аня", "Боря"]` | сначала время, потом имя |
| `b.note` | `"рекорд"` | поле хранится, но в сравнении не участвует |

**Порядок полей решает.** Если поставить `name` первым, таблица отсортируется по имени, а не по времени. Поэтому поля записывают от главного критерия к второстепенным.

## compare=False: поле, которое не сравнивается

`field(compare=False)` исключает поле из `==`, `<` и других сравнений (и из хеша). Так делают для пометок, комментариев, времени создания: данные есть, но два «одинаковых по смыслу» объекта с разными пометками остаются равными.

```python
Run(60, "Аня", "первая попытка") == Run(60, "Аня", "вторая попытка")    # True
```

Поле с `field(...)` и значением по умолчанию пишут так: `note: str = field(default="", compare=False)`. Поля с умолчанием в dataclass идут **после** полей без умолчания.

## Что order=True не умеет

Только один порядок «слева направо по возрастанию». Если нужно «очки по убыванию, имя по возрастанию», `order=True` не подходит: пиши `__lt__` с явной веткой или используй `sorted(records, key=...)`. Хеш обычный `@dataclass` отключает, как и любой класс с `__eq__`; `@dataclass(frozen=True, order=True)` даёт неизменяемую сортируемую запись, которую можно класть в множество.

## Частые ошибки

Поставить поля не в том порядке: сортировка идёт, но по неожиданному критерию.

Ждать, что `order=True` сравнит поля по убыванию: нет, всегда по возрастанию.

Забыть `order=True` и вызвать `sorted(records)`: будет `TypeError: '<' not supported`.

## Проверь себя

```python
@dataclass(order=True)
class Entry:
    level: int
    name: str
    hint: str = field(default="", compare=False)

x = Entry(2, "б", "первая")
y = Entry(2, "б", "вторая")
z = Entry(1, "я")
```

1. Чему равно `x == y`?
2. Чему равно `z < x`?
3. Что вернёт `sorted([x, z])[0].name`?

<details><summary>Ответ</summary>

1. `True`: поле `hint` не сравнивается.
2. `True`: `1 < 2`, первое поле решило.
3. `"я"`: у `z` меньше `level`.

</details>
