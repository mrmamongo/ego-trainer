# `__hash__`: объекты в множествах и ключах словаря

Множество (`set`) и ключи словаря работают быстро потому, что у каждого элемента есть **хеш**: число, по которому Python сразу находит нужную «ячейку». Хеш элемента Python берёт методом `__hash__`. Для чисел и строк он уже есть, а для объектов твоего класса возможны три случая.

| Класс | `==` | Можно ли положить в `set` | Что считается «одним и тем же» |
|---|---|---|---|
| обычный, без `__eq__` | как `is` | да | только один и тот же объект |
| с `__eq__`, без `__hash__` | по смыслу | **нет**: `TypeError: unhashable type` | |
| с `__eq__` и `__hash__` | по смыслу | да | объекты, равные по `__eq__` |

Второй случай — ловушка: **как только ты пишешь `__eq__`, Python отключает хеш**, потому что старый хеш (по адресу в памяти) больше не согласован с новым равенством.

## Главное правило

**Равные объекты обязаны иметь равный хеш.** Проще всего собрать хеш из тех же полей, по которым работает `__eq__`:

```python
class Message:
    def __init__(self, author, text):
        self.author = author
        self.text = text

    def __eq__(self, other):
        if not isinstance(other, Message):
            return NotImplemented
        return self.author == other.author and self.text == other.text

    def __hash__(self):
        return hash((self.author, self.text))

a = Message("Аня", "привет")          # 1
b = Message("Аня", "привет")          # 2
c = Message("Боря", "привет")         # 3
seen = {a, b, c}                      # 4
```

| После строки | Что получилось |
|---|---|
| 4 | `len(seen)` равно `2`: `a` и `b` равны по смыслу и в множестве слились |
| 4 | `Message("Аня", "привет") in seen` равно `True`: множество нашло объект по хешу и проверило `__eq__` |

Функция `hash((a, b))` берёт хеш кортежа, а кортеж собирается из полей. Это самый простой способ: порядок и набор полей те же, что в `__eq__`.

С такой парой объект можно сделать и **ключом словаря**: `counts[Message("Аня", "привет")] = 1`. Два равных объекта дадут один и тот же ключ.

## frozen dataclass уже всё умеет

`@dataclass(frozen=True)` пишет `__eq__` **и** `__hash__` по всем полям, поэтому такие записи спокойно лежат в множествах и ключах. Обычный `@dataclass` без `frozen` `__eq__` пишет, а хеш отключает, как в ловушке выше. Подробнее про frozen в карточке «frozen: запись, которую нельзя менять».

## Частые ошибки

Объявить `__eq__` и забыть `__hash__`:

```python
seen = {Message("Аня", "привет")}     # TypeError: unhashable type: 'Message'
```

Хеш и равенство по разным полям. Если хеш берёт **больше** полей, чем `__eq__`, то равные объекты получат разный хеш и не найдутся друг в друге. Если **меньше** (только `text`), всё работает, но объекты с разными авторами и одним текстом будут «толпиться» в одной ячейке. Поля берут одни и те же.

Менять поля объекта, пока он лежит в множестве: хеш изменится, и объект «потеряется». Поэтому ключами делают неизменяемые вещи.

## Проверь себя

```python
class Tag:
    def __init__(self, name):
        self.name = name

    def __eq__(self, other):
        return isinstance(other, Tag) and self.name == other.name

    def __hash__(self):
        return hash(self.name)
```

1. Чему равно `len({Tag("a"), Tag("a"), Tag("b")})`?
2. Что случится, если убрать метод `__hash__`?

<details><summary>Ответ</summary>

1. `2`: две метки `"a"` равны по смыслу и слились в одну.
2. Множество не получится собрать: будет `TypeError: unhashable type: 'Tag'`, потому что класс с `__eq__` без `__hash__` нехешируем.

</details>
