# `__lt__` и сортировка объектов

Список чисел или строк сортируется сам: `sorted([3, 1, 2])`. Список объектов твоего класса Python сортировать не умеет: он не знает, какой объект «меньше».

```python
sorted([Item("чай", 80), Item("кофе", 120)])
# TypeError: '<' not supported between instances of 'Item' and 'Item'
```

Научить его можно методом `__lt__(self, other)` («less than», «меньше»): Python вызывает его, когда видит `a < b`, а `sorted` и `min` сравнивают элементы именно через `<`. Метод возвращает `True`, если `self` должен стоять **раньше** `other`.

```python
class Item:
    def __init__(self, name, price):
        self.name = name
        self.price = price

    def __lt__(self, other):
        return (self.price, self.name) < (other.price, other.name)

tea = Item("чай", 80)              # 1
jam = Item("варенье", 80)          # 2
cof = Item("кофе", 120)            # 3
names = [i.name for i in sorted([cof, tea, jam])]     # 4
```

| Что сравнивается | Результат | Почему |
|---|---|---|
| `tea < cof` | `True` | `(80, "чай") < (120, "кофе")`, цена меньше |
| `tea < jam` | `False` | цены равны, дальше `"чай" < "варенье"` ложно |
| `jam < tea` | `True` | цены равны, `"варенье"` по алфавиту раньше |
| `names` | `["варенье", "чай", "кофе"]` | по цене, а при равных ценах по названию |

## Кортеж как правило сортировки

Сравнивать надо **кортежи**: Python сравнивает их по первому элементу, при равенстве по второму, и так далее. Это и есть «главный критерий, потом второй»: так при одинаковых очках игроки идут по имени, а не как попало.

Если нужен порядок «по убыванию очков, при равенстве по имени», числа переворачивают минусом, а строки нельзя. Тогда пишут явную ветку:

```python
def __lt__(self, other):
    if self.score != other.score:
        return self.score > other.score      # больше очков значит «раньше»
    return self.name < other.name
```

## Другой путь: key=

Порядок можно не вшивать в класс, а задавать при сортировке: `sorted(items, key=lambda i: (i.price, i.name))`. Это проще, когда порядков несколько. `__lt__` удобен, когда у класса есть один естественный порядок.

## Остальные сравнения

Достаточно одного `__lt__`: `a > b` Python сам превращает в `b < a`, а `sorted`, `min` и `max` работают. Остальные операции (`<=`, `>=`) бесплатно даёт декоратор `functools.total_ordering`: напиши `__eq__` и `__lt__`, добавь `@total_ordering` над классом.

## Частые ошибки

Сравнить не те поля или забыть второй критерий: тогда при равных значениях порядок случайный, как во входном списке.

Вернуть не `True`/`False`, а число или сам объект: `__lt__` должен отвечать на вопрос «раньше ли я?».

## Проверь себя

```python
class Task:
    def __init__(self, title, prio):
        self.title = title
        self.prio = prio

    def __lt__(self, other):
        return (self.prio, self.title) < (other.prio, other.title)

a = Task("б", 2)
b = Task("а", 2)
c = Task("я", 1)
```

1. Чему равно `a < b`?
2. В каком порядке `sorted([a, b, c])` вернёт названия?

<details><summary>Ответ</summary>

1. `False`: приоритеты равны, а `"б" < "а"` ложно.
2. `["я", "а", "б"]`: сначала приоритет 1, потом при равных по названию.

</details>
