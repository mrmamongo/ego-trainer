# `__eq__`: равенство по смыслу

В карточке «Два имени — один объект, is и ==» мы выяснили: пока класс не научили сравнивать себя, `==` работает как `is`. Два объекта с одинаковыми полями считаются разными. Научить класс отвечать «равны по смыслу» можно методом `__eq__(self, other)`: Python вызывает его, когда видит `a == b`.

```python
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __eq__(self, other):
        if not isinstance(other, Point):
            return NotImplemented
        return self.x == other.x and self.y == other.y

a = Point(1, 2)              # 1
b = Point(1, 2)              # 2
c = a                        # 3
```

| Выражение | Результат | Почему |
|---|---|---|
| `a == b` | `True` | `__eq__` сравнил поля |
| `a is b` | `False` | это два разных объекта: `is` не знает про `__eq__` |
| `a is c` | `True` | второе имя того же объекта |
| `a != Point(1, 3)` | `True` | `!=` Python выводит из `__eq__` сам, отдельный метод не нужен |
| `a == (1, 2)` | `False` | другой тип: `__eq__` ответил `NotImplemented` |
| `Point(1, 2) in [a]` | `True` | `in` и `count` тоже зовут `__eq__` |

## Зачем NotImplemented

Если справа стоит объект другого типа, `other.x` упадёт с `AttributeError`. Поэтому в начале `__eq__` проверяют тип. Но возвращать при несовпадении типа `False` не нужно: пиши `return NotImplemented`. Это не ошибка, а сообщение Python: «я не умею сравнивать с таким, спроси другую сторону». Python попробует `__eq__` второго объекта, а если и тот не умеет, итог будет `False`. Так твой класс не мешает чужим классам сравнивать себя с ним.

`NotImplemented` не то же самое, что исключение `NotImplementedError`. Возвращают именно `NotImplemented`, без `raise`.

## Частые ошибки

Забыть проверку типа:

```python
def __eq__(self, other):
    return self.x == other.x and self.y == other.y     # Point(1, 2) == 5 упадёт с AttributeError
```

Сравнить лишнее. Если в объекте есть поле, которое не влияет на смысл (время отправки сообщения), его не включают в сравнение.

Важное следствие: как только ты написал `__eq__`, объект перестаёт быть хешируемым. Подробности в карточке про `__hash__`.

## Проверь себя

```python
p = Point(3, 4)
q = Point(3, 4)
r = q
```

1. Чему равны `p == q` и `p is q`?
2. Чему равно `[p, q, r].count(p)`?
3. Что даст `p == "3,4"`?

<details><summary>Ответ</summary>

1. `True` и `False`.
2. `3`: все три объекта равны `p` по полям.
3. `False`: `__eq__` вернул `NotImplemented`, и итог сравнения с чужим типом `False`.

</details>
