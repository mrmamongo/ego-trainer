# Задача CL11: Банковский счёт

## Условие

### Как это работает

Метод может отказаться работать: если данные недопустимы, он бросает `raise ValueError("сообщение")`, ровно как функция из папки про ошибки. Объект при этом **не меняется**: проверка стоит до изменения, и `raise` обрывает метод.

```python
class Jar:
    def __init__(self, left):
        self.left = left

    def take(self, k):
        if k > self.left:
            raise ValueError("мало")
        self.left = self.left - k
```

Проверка сценария ловит ошибку и записывает её в результат как `["error", тип, сообщение]`. Сценарий при этом продолжается.

| Действие | Результат | `left` после |
|---|---|---|
| `["new", 3]` | `"ok"` | `3` |
| `["take", 5]` | `["error", "ValueError", "мало"]` | `3`: объект цел |
| `["take", 2]` | `None` | `1` |

### Задание

Напиши класс `BankAccount` — банковский счёт:

- `__init__(owner, balance)` запоминает `owner` и `balance` в атрибутах с теми же именами;
- `deposit(amount)` пополняет счёт; если `amount` не больше нуля, бросает `ValueError("сумма должна быть больше нуля")`, баланс при этом не меняется;
- `withdraw(amount)` списывает деньги; если `amount` больше `balance`, бросает `ValueError("недостаточно денег")`, баланс не меняется.

Оба метода ничего не возвращают.

## Аргументы

- `actions` — список действий сценария. Его подаёт проверка, ты его не пишешь. Как читать сценарий, объяснено в карточке «Как читать сценарий».

## Возвращает

Список результатов: по одному на каждое действие сценария, в том же порядке. Функция-рамка в конце файла уже готова.

## Правила

- Пиши только класс `BankAccount`; рамку внизу файла не трогай.
- Сообщения об ошибках должны совпадать с условием слово в слово.
- Нужны методы `__init__`, `deposit` и `withdraw`.

## Пример

| Действие | Результат |
|---|---|
| `["new", "Аня", 100]` | `"ok"` |
| `["deposit", 50]` | `None` |
| `["get", "balance"]` | `150` |
| `["withdraw", 500]` | `["error", "ValueError", "недостаточно денег"]` |
| `["get", "balance"]` | `150` |

## Учебные цели

- Бросать `ValueError` из метода и видеть ошибку в результате сценария.
- Ставить проверку **до** изменения состояния, чтобы отказ не портил объект.

## Проверка понимания

Что покажет `["get", "balance"]` после неудачного `withdraw`? Что было бы, если списать деньги до проверки?
