# Задача CL15: Метод не находит соседа

## Условие

### Как это работает

Метод класса не видит другие методы по одному имени. Чтобы вызвать метод того же объекта, перед ним пишут `self.`:

```python
class Lamp:
    def __init__(self, power):
        self.power = power

    def is_on(self):
        return self.power > 0

    def status(self):
        return is_on()          # NameError: имя is_on нигде не определено
```

Правильно: `return self.is_on()`. Ошибка в сценарии видна как результат вида `["error", "NameError", "..."]`.

| Действие | Результат |
|---|---|
| `["new", 3]` | `"ok"` |
| `["status"]` | сейчас `["error", "NameError", "name 'is_on' is not defined"]`, а должно быть `True` |

### Задание

Метод `hit(damage)` уменьшает `hp` и должен вернуть `True`, если игрок ещё жив, и `False`, если нет (для этого есть `is_alive()`). Сейчас `hit` падает с `NameError`. Найди ошибку и исправь.

## Аргументы

- `actions` — список действий сценария. Его подаёт проверка, ты его не пишешь. Как читать сценарий, объяснено в карточке «Как читать сценарий».

## Возвращает

Список результатов: по одному на каждое действие сценария, в том же порядке. Функция-рамка в конце файла уже готова.

## Правила

- Меняй только способ вызова `is_alive`; остальной код оставь как есть.
- Рамку внизу файла не трогай.

## Пример

| Действие | Результат |
|---|---|
| `["new", 10]` | `"ok"` |
| `["hit", 4]` | `True` |
| `["hit", 6]` | `False` |
| `["get", "hp"]` | `0` |

## Учебные цели

- Узнавать `NameError` из-за забытого `self.` при вызове своего метода.
- Вызывать один метод из другого через `self`.

## Проверка понимания

Изменится ли `hp` после неудачного вызова исходного `hit`, если ошибка случилась на последней строке? Почему это опасно?
