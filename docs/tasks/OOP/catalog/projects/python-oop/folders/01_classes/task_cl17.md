# Задача CL17: Статусы квеста

## Условие

### Как это работает

Объект часто живёт по **статусам**: «новый → в работе → готов». Статус хранят в атрибуте-строке, а методы-переходы проверяют, из какого статуса их вызвали. Недопустимый переход — это `ValueError`, а в сообщение удобно подставить текущий статус через f-строку.

```python
class Order:
    def __init__(self):
        self.status = "new"

    def pay(self):
        if self.status != "new":
            raise ValueError(f"нельзя оплатить заказ из статуса {self.status}")
        self.status = "paid"
```

| Действие | Результат | `status` после |
|---|---|---|
| `["new"]` | `"ok"` | `"new"` |
| `["pay"]` | `None` | `"paid"` |
| `["pay"]` | `["error", "ValueError", "нельзя оплатить заказ из статуса paid"]` | `"paid"` |

### Задание

Напиши класс `Quest` с жизненным циклом «new → active → done»:

- `__init__(title)` запоминает `title` и ставит `status = "new"`;
- `start()` переводит квест из `"new"` в `"active"`; из любого другого статуса бросает `ValueError("нельзя начать квест из статуса X")`, где `X` — текущий статус;
- `finish()` переводит квест из `"active"` в `"done"`; из любого другого статуса бросает `ValueError("нельзя завершить квест из статуса X")`;
- `is_done()` возвращает `True`, если статус `"done"`, иначе `False`.

При ошибке статус не меняется. `start` и `finish` ничего не возвращают.

## Аргументы

- `actions` — список действий сценария. Его подаёт проверка, ты его не пишешь. Как читать сценарий, объяснено в карточке «Как читать сценарий».

## Возвращает

Список результатов: по одному на каждое действие сценария, в том же порядке. Функция-рамка в конце файла уже готова.

## Правила

- Пиши только класс `Quest`; рамку внизу файла не трогай.
- Сообщения об ошибках должны совпадать с условием слово в слово.
- Нужны методы `__init__`, `start`, `finish` и `is_done`.

## Пример

| Действие | Результат |
|---|---|
| `["new", "Охота"]` | `"ok"` |
| `["finish"]` | `["error", "ValueError", "нельзя завершить квест из статуса new"]` |
| `["start"]` | `None` |
| `["finish"]` | `None` |
| `["is_done"]` | `True` |

## Учебные цели

- Описать жизненный цикл объекта статусами и методами-переходами.
- Бросать `ValueError` с сообщением, в которое подставлено состояние объекта.

## Проверка понимания

Какой статус будет у квеста после `new, start, start`? Что вернёт `is_done()` у активного квеста?
