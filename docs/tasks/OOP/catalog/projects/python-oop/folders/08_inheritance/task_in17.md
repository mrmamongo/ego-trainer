# Задача IN17: Статусы заказа

## Условие

### Как это работает

Иногда родитель задаёт только **правила**: «у любого наследника должны быть методы такие-то», а сам их не умеет делать. Для этого класс наследуют от `ABC`, а обязательные методы помечают `@abstractmethod`. Такой класс создать нельзя, а наследник обязан написать все абстрактные методы, иначе и его создать не получится.

```python
from abc import ABC, abstractmethod


class Shape(ABC):
    @abstractmethod
    def area(self):
        pass

    def describe(self):                  # обычный метод, опирается на абстрактный
        return "площадь " + str(self.area())


class Square(Shape):
    def __init__(self, side):
        self.side = side

    def area(self):
        return self.side * self.side
```

| Выражение | Что произойдёт |
|---|---|
| `Shape()` | `TypeError`: абстрактный класс создать нельзя |
| `Square(3).area()` | `9` |
| `Square(3).describe()` | `"площадь 9"` |

Текст у `TypeError` зависит от версии Python, поэтому рамка этой задачи показывает только тип ошибки: `["error", "TypeError"]`.

### Задание

Напиши абстрактный класс статуса заказа и три конкретных статуса. Импорт `ABC` и `abstractmethod` уже есть в файле.

- `Status` — абстрактный класс. Абстрактные методы: `label()` и `can_cancel()`. Обычный метод `describe()` возвращает `label() + ", отмена: да"` или `", отмена: нет"`, смотря на `can_cancel()`;
- `Created` — `label()` возвращает `"создан"`, `can_cancel()` возвращает `True`;
- `Paid` — `"оплачен"`, отмена возможна (`True`);
- `Shipped` — `"отправлен"`, отмена невозможна (`False`).

## Аргументы

- `actions` — список действий сценария. Его подаёт проверка, ты его не пишешь. Как читать сценарий, объяснено в карточках «Как читать сценарий» и «Рамка для нескольких классов».

## Возвращает

Список результатов: по одному на каждое действие сценария, в том же порядке. Функция-рамка в конце файла уже готова. Попытка создать абстрактный класс даёт результат `["error", "TypeError"]`.

## Правила

- Пиши только классы; рамку внизу файла не трогай.
- Оба метода `Status` должны быть абстрактными (`@abstractmethod`), а `describe` — обычным.
- В рамке есть готовый класс `GivenHalf`: он проверяет, что твой `Status` действительно требует оба метода.

## Пример

| Действие | Результат |
|---|---|
| `["new", "Created"]` | `"ok"` |
| `["describe"]` | `"создан, отмена: да"` |
| `["new", "Shipped"]` | `"ok"` |
| `["describe"]` | `"отправлен, отмена: нет"` |
| `["new", "Status"]` | `["error", "TypeError"]` |

## Учебные цели

- Объявить абстрактный класс через `ABC` и `@abstractmethod`.
- Написать обычный метод родителя, который опирается на абстрактные методы наследников.

## Проверка понимания
