# Задача IN18: Ярость воина

## Условие

### Как это работает

Сейчас воин бьёт всегда на 12: его `attack` полностью заменяет родительский и не смотрит на уровень.

```python
class Warrior(Unit):
    def attack(self):
        return 12
```

**Где реализовано старое правило:** весь метод `attack` в `Warrior` (одно число).

**Что меняется:** удар воина должен расти вместе с уровнем, поэтому он строится на ударе родителя: `super().attack() + 4 + self.rage`. У воина появляется своё поле `rage` (ярость): третий параметр `__init__` со значением по умолчанию `0`. Свой `__init__` обязан позвать `super().__init__(name, level)`.

**Что нельзя трогать:** класс `Unit` и поведение обычного юнита. Воин четвёртого уровня без ярости по-прежнему бьёт на 12, ведь `4 + 4 + 4 = 12`.

### Задание

Раньше воин бил всегда на 12. Теперь его удар равен удару родителя плюс 4 плюс ярость `rage`, а `rage` — необязательный третий параметр воина (по умолчанию `0`). Измени класс `Warrior`.

## Аргументы

- `actions` — список действий сценария. Его подаёт проверка, ты его не пишешь. Как читать сценарий, объяснено в карточках «Как читать сценарий» и «Рамка для нескольких классов».

## Возвращает

Список результатов: по одному на каждое действие сценария, в том же порядке. Функция-рамка в конце файла уже готова.

## Правила

- Измени только `Warrior`; `Unit` и рамку внизу файла не трогай.
- Удар родителя бери через `super()`, не пиши формулу `4 + level` заново.
- Старые вызовы `Warrior("Грок", 4)` должны продолжать работать.

## Пример

| Действие | Результат |
|---|---|
| `["new", "Warrior", "Грок", 4]` | `"ok"` |
| `["attack"]` | `12` |
| `["new", "Warrior", "Ярый", 2, 3]` | `"ok"` |
| `["attack"]` | `13` |
| `["get", "rage"]` | `3` |

## Учебные цели

- Превратить замену метода в расширение через `super()`.
- Добавить наследнику новое поле с параметром по умолчанию, не сломав старые вызовы.

## Проверка понимания

Сколько бьёт `Warrior("Грок", 10)` без ярости? Что случится, если в `Warrior.__init__` забыть `super().__init__(name, level)`?
