# Задача IN12: Допиши вызов родителя

## Условие

### Как это работает

Свой `__init__` наследника обычно начинается с вызова родительского: `super().__init__(...)`, куда передают всё, что родитель хранит сам. Потом наследник дописывает **только свои** поля.

```python
class Item:
    def __init__(self, name):
        self.name = name


class Sword(Item):
    def __init__(self, name, power):
        super().__init__(name)       # name — забота родителя
        self.power = power           # power — своё поле
```

После `Sword("меч", 3)` у объекта оба поля: `name` и `power`. Если строку с `super()` убрать, `name` пропадёт.

### Задание

В классе `Push` не хватает вызова родительского `__init__`: пока адресат `to` не запоминается. Замени `pass` одной строкой с `super()`.

## Аргументы

- `actions` — список действий сценария. Его подаёт проверка, ты его не пишешь. Как читать сценарий, объяснено в карточках «Как читать сценарий» и «Рамка для нескольких классов».

## Возвращает

Список результатов: по одному на каждое действие сценария, в том же порядке. Функция-рамка в конце файла уже готова.

## Правила

- Замени `pass` в `Push.__init__` одной строкой, остальной код не меняй.
- Рамку внизу файла не трогай.

## Пример

| Действие | Результат |
|---|---|
| `["new", "Push", "anya", "chat"]` | `"ok"` |
| `["get", "to"]` | `"anya"` |
| `["send", "привет"]` | `"chat/anya: привет"` |

## Учебные цели

- Вызвать `super().__init__(...)` с нужными аргументами.
- Разделять поля: что запоминает родитель, а что наследник.

## Проверка понимания

Почему `to` не нужно записывать в `Push` через `self.to = to`? Что вернёт `send` без `super().send(...)` внутри `Push.send`?
