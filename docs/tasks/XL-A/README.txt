XL-A — продуктовая практика на Python
====================================

27 задач: 9 на поиск бага, 9 на изменение кода, 9 на новый код.
Домены: LLM, агенты, игровые механики и сервисы MMO.

Предполагаемая база: предыдущие блоки, включая J1–J14 Extended и S1–S6,
считаются пройденными. Здесь комбинируются знакомые приёмы и способы работы
с кодом. Ответы моделей и игровые события передаются готовыми данными.

Как работать с файлами
----------------------
Каждая папка содержит самостоятельный student.py с тремя заданиями.
Для заданий есть отдельные функции task_xlaNN_... и подробные docstring.
Не нужно переносить свои решения из других папок. Помощники GIVEN —
подготовленная рабочая версия нужного компонента; их можно изучать и вызывать.

Найти баг:
  Прочитать договор и исходный код. Подготовить вход, который воспроизводит
  нарушение, указать ожидаемый результат, исправить код и объяснить причину.
  У баговых исходных реализаций намеренно есть ошибка.

Правки:
  Расширить имеющуюся реализацию согласно новому договору и сохранить
  оговорённые старые случаи. XL-A25 — рефакторинг с сохранением поведения;
  качество декомпозиции дополнительно обсуждается с ментором.

Новый код:
  Реализовать функцию с pass. Там, где указаны обязательные помощники,
  собрать решение из их вызовов, не переписывая предметную логику.

Проверка
--------
Девять исходных student.py содержат условия, заготовки и примеры.
В catalog/ подготовлен отдельный комплект для Cogito: условия .md,
стартовые .student.py, эталоны .solution.py и smoke/full тесты .tests.py.
Прямой запуск исходного student.py только загрузит определения.
Примеры из docstring можно вызывать в Python или оформить своими assert.
Для бага пример должен отличать исходную реализацию от исправленной.

Для всех видов задач важны порядок результата, поведение при отказах,
пустые входы, равенство порогу и сохранность исходных данных. Если условие
обещает корректный формат входа, валидацию других форматов добавлять не нужно.
Правила одной миниистории не переносятся автоматически в другую: каждый
договор задаёт свои структуры и коды ошибок.

Для импорта в Cogito используй catalog/catalog.yaml и каталог проектов
рядом с ним. Исходные девять student.py сохраняются как полные миниистории.
