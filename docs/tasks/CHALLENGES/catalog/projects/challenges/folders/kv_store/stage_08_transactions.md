# Задача KV08: Транзакции

## Условие

### Что добавить

Последний этап. Иногда нужно выполнить несколько команд **разом**: сначала собрать их в очередь, а потом запустить все вместе или выбросить. Это называется транзакция.

Три новые команды живут в `main.py`, потому что им нужна память, которой нет у `execute`: очередь.

| Команда | Что делает | Ответ |
|---|---|---|
| `MULTI` | начинает транзакцию | `OK` |
| любая другая команда, пока идёт транзакция | не выполняется, а встаёт в очередь | `QUEUED` |
| `EXEC` | выполняет все команды из очереди по порядку и заканчивает транзакцию | ответ каждой команды, **каждый на своей строке**; если очередь пустая, `(empty)` |
| `DISCARD` | выбрасывает очередь и заканчивает транзакцию | `OK` |

Ошибки (тексты должны совпадать до символа):

| Что случилось | Ответ |
|---|---|
| `EXEC` без `MULTI` | `ERR EXEC without MULTI` |
| `DISCARD` без `MULTI` | `ERR DISCARD without MULTI` |
| `MULTI` во время транзакции | `ERR MULTI calls can not be nested` (очередь остаётся как была) |

Ошибка внутри очереди (например, неизвестная команда) не мешает остальным: в очередь команда встаёт как обычная и отвечает `QUEUED`, а текст ошибки ты увидишь при `EXEC`.

Пример сессии:

| Ты вводишь | Программа печатает |
|---|---|
| `MULTI` | `OK` |
| `SET a 1` | `QUEUED` |
| `INCR a` | `QUEUED` |
| `GET a` | `QUEUED` |
| `EXEC` | `OK` |
| | `2` |
| | `2` |
| `GET a` | `2` |
| `EXEC` | `ERR EXEC without MULTI` |

А если вместо `EXEC` ввести `DISCARD`, то `SET a 1` не выполнится, и `GET a` ответит `(nil)`.

### Подсказка

Меняй файл `main.py`. Заведи перед циклом переменную `queue = None`: `None` значит «транзакции нет», а список (даже пустой) — «транзакция идёт». Строки очереди удобно хранить парами `(имя, аргументы)`: так `EXEC` сможет вызвать `execute(store, имя, аргументы)` для каждой. `EXIT` выходит из программы и при открытой транзакции, очередь просто пропадает.

## Правила

- Команды `MULTI`, `EXEC` и `DISCARD` обрабатывает `main.py`, а `execute` остаётся как был.
- Пока идёт транзакция, команды **не выполняются**, а только встают в очередь.
- После `EXEC` и после `DISCARD` команды снова выполняются сразу.
- Все прошлые этапы работают как раньше.

## Пример

```text
MULTI
SET a 1
DISCARD
GET a
```

печатает:

```text
OK
QUEUED
OK
(nil)
```

## Учебные цели

- Хранить состояние программы в переменной между итерациями цикла.
- Различать режимы работы программы: обычный и «в транзакции».
- Выполнять накопленные команды по порядку.

## Проверка понимания

Почему `SET` внутри транзакции отвечает `QUEUED`, а не `OK`? Чем различаются `queue = None` и `queue = []`?
