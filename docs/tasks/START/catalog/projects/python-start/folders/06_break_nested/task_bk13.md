# Задача BK13: Пары и break во вложенном цикле

## Условие

### Как это работает

Во вложенных циклах внутренний выполняется **целиком** на каждый проход внешнего. А `break` выходит только из внутреннего цикла: внешний продолжает работу.

```python
count = 0
for i in [1, 2]:
    for j in [5, 6, 7]:
        count = count + 1
        if j == 6:
            break
```

| Выполнение строки `count = count + 1` | i | j | count |
|---|---|---|---|
| 1 | 1 | 5 | 1 |
| 2 | 1 | 6 | 2, затем `break` (на 7 не доходим) |
| 3 | 2 | 5 | 3 |
| 4 | 2 | 6 | 4, затем `break` |

Для `i = 1` внутренний цикл выполнил тело два раза, потом `break`; внешний цикл сам взял `i = 2` и запустил внутренний с самого начала.

### Задание

В файле вложенные циклы с `break`. Впиши вместо `None`: `i_at_run_4` и `j_at_run_4` — значения `i` и `j` при **четвёртом** выполнении строки 4,
`runs_with_i2` — сколько раз строка 4 выполнилась, пока `i` было равно 2, `count_final` — значение `count` после всех циклов,
`j_final` — значение `j` после всех циклов.

**Сначала реши в голове или на бумаге, код не запускай.** Построй таблицу выполнений строки 4: так ошибиться труднее.

## Правила

- Меняй только строчки с `None`.
- Строки `def task_bk13_trace():` и `return ...` самой рамки не трогай: так проверка читает твои ответы.

## Учебные цели

- Отслеживать пары (внешняя, внутренняя переменная) по порядку.
- Понимать, что `break` обрывает только внутренний цикл.

## Проверка понимания

Сколько выполнений строки 4 было бы без `break`? Почему внешний цикл всё равно дошёл до `i = 3`?
