# break: выйти из цикла досрочно

Обычно `for` проходит по **всем** элементам списка. Но иногда дальше идти нет смысла: нашли то, что искали, или встретили стоп-сигнал.
Тогда цикл можно оборвать командой `break`.

## break выходит из цикла, а не из функции

```python
def sum_before_negative(numbers):
    total = 0
    for number in numbers:           # 1
        if number < 0:               # 2
            break                    # 3
        total = total + number       # 4
    return total                     # 5
```

Пусть `numbers = [5, 3, -2, 7]`:

| Проход | number | `number < 0`? | total после прохода |
|---|---|---|---|
| 1 | 5 | нет | 5 |
| 2 | 3 | нет | 8 |
| 3 | -2 | да, `break` | 8 (строка 4 в этом проходе не выполнилась) |
| — | `7` цикл даже не увидел | | |

После `break` Python сразу прыгает на **первую строку после цикла** (строка 5) и продолжает работу: функция вернёт `8`.
Переменная цикла остаётся на том значении, на котором остановились: после цикла `number` равно `-2`.

## break или return

| Команда | Что покидает | Что выполняется дальше |
|---|---|---|
| `break` | только ближайший цикл | код сразу после цикла |
| `return` | всю функцию | ничего: функция закончена |

Если после цикла нужно ещё что-то посчитать (как `return total` выше), берём `break`.
Если ответ уже известен и дальше делать нечего (нашли, что искали), можно сразу `return`.

## while True и break

Цикл `while True:` не заканчивается сам: условие всегда истинно. Выйти из него можно только через `break` (или `return`).

```python
n = 1                    # 1
while True:              # 2
    n = n * 2            # 3
    if n > 50:           # 4
        break            # 5
```

| Проход | n после строки 3 | `n > 50`? |
|---|---|---|
| 1 | 2 | нет |
| 2 | 4 | нет |
| 3 | 8 | нет |
| 4 | 16 | нет |
| 5 | 32 | нет |
| 6 | 64 | да, `break` |

Правило безопасности: в `while True` проверь две вещи. Переменная из условия `if` **должна меняться** в теле (здесь `n` растёт).
И `break` должен стоять там, куда программа реально дойдёт, иначе цикл не закончится никогда.

## Куда поставить break

Порядок строк важен. Число, на котором мы остановились, попадёт в сумму или нет — зависит от того, **до** или **после** `break` стоит строка с прибавлением.
В `sum_before_negative` проверка стоит раньше прибавления, поэтому `-2` в сумму не вошло.

## Частые ошибки

`break` без условия: цикл заканчивается на первом же проходе.

```python
for number in numbers:
    break                       # неверно: выйдем сразу, на первом элементе
    total = total + number
```

`break` вместо `return`: он не вернёт ответ из функции.

```python
def has_negative(numbers):
    for number in numbers:
        if number < 0:
            break               # неверно: цикл закончился, но ответ не задан
    return False                # всегда False
```

```python
def has_negative(numbers):
    for number in numbers:
        if number < 0:
            return True         # верно: выходим из функции с ответом
    return False
```

## Проверь себя

```python
total = 0
for n in [2, 5, 0, 4]:
    if n == 0:
        break
    total = total + n
```

1. Чему равно `total` после цикла?
2. Чему равно `n` после цикла?
3. Сколько проходов цикл начал?

<details><summary>Ответ</summary>

1. `7` (`2 + 5`, а на нуле цикл оборвался).
2. `0`: переменная цикла осталась на элементе, где сработал `break`.
3. Три: на третьем проходе (`n = 0`) цикл начался, но тело досрочно оборвалось.

</details>
