# Задача BK04: Сумма останавливается на минусе

## Условие

### Как это работает

Нужно **пропустить** отрицательные числа и сложить все остальные. Но `break` не пропускает число, а останавливает цикл целиком:

```python
def sum_non_negative(numbers):
    total = 0
    for number in numbers:
        if number < 0:
            break              # плохо: цикл оборвался, оставшиеся числа потеряны
        total = total + number
    return total
```

| Проход | number | total после прохода |
|---|---|---|
| 1 | 5 | 5 |
| 2 | -1 | `break`, цикл закончился: итог 5 |

А числа `4`, `2` после минуса так и не были сложены. Чтобы **пропустить** одно число и идти дальше, нужен `continue`.

### Задание

Функция `task_bk04_sum_skip_negative(numbers)` должна вернуть сумму всех неотрицательных чисел, но останавливается на первом отрицательном.
Найди ошибку и исправь.

## Аргументы

- `numbers` — список целых чисел (может быть пустым).

## Возвращает

Сумму чисел, которые не меньше нуля; если таких нет, то `0`.

## Правила

- Исправление маленькое: поменяй одно слово, остальной код оставь как есть.
- Встроенную функцию `sum` не используй.
- Функция должна **вернуть** значение через `return`, а не печатать его.

## Пример

```python
task_bk04_sum_skip_negative([1, 2, 3])        # -> 6
task_bk04_sum_skip_negative([5, -1, 4, 2])    # -> 11
task_bk04_sum_skip_negative([-3, -4])         # -> 0
```

## Учебные цели

- Замечать, что `break` вместо `continue` обрывает цикл и теряет остальные элементы.
- Исправлять ошибку, понимая, чем отличается «остановиться» от «пропустить».

## Проверка понимания

Что вернёт исходная функция для `[5, -1, 4, 2]` и почему? Что она вернёт для `[1, 2, 3]`?
