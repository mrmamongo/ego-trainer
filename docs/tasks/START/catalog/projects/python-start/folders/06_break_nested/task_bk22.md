# Задача BK22: Первая цена обязательна

## Условие

### Как это работает

**Что изменилось по сравнению с BK21: первая цена `prices[0]` берётся всегда.**

Из этого следует четыре изменения:

1. **Особые случаи в начале.** Если список пуст, вернуть `[]`. Если `prices[0]` одна уже больше бюджета, обязательное взять нельзя: вернуть `[]`.
2. **Бюджет уже частично потрачен.** Накопитель начинается не с нуля, а с `prices[0]`: `total = prices[0]`.
3. **Обходим остальные цены с конца, не трогая `prices[0]`.** Для этого вместо `reversed(prices)` ходим по номерам: `for index in range(len(prices) - 1, 0, -1)` (номер `0` не входит), цена — `prices[index]`.
4. **Не забыть `prices[0]` в ответе.** В списке, собранном с конца, самая старая цена должна стоять **последней**. Поэтому после цикла добавь `prices[0]` в конец `result` и только потом разверни `result.reverse()`.

Остальное как в BK21: пропуск цены, которая не влезла (`continue`), проверка `total + price > budget`.

Пример: `prices = [6, 1, 1, 5]`, `budget = 10`. Сначала `total = 6`. Идём по номерам 3, 2, 1.

| Номер | price | `total + price` | влезает? | что делаем | total | result |
|---|---|---|---|---|---|---|
| 3 | 5 | 11 | нет | пропускаем | 6 | `[]` |
| 2 | 1 | 7 | да | берём | 7 | `[1]` |
| 1 | 1 | 8 | да | берём | 8 | `[1, 1]` |

После цикла: добавляем `prices[0]`, получается `[1, 1, 6]`, `reverse()` даёт `[6, 1, 1]`.

На тех же данных BK21 вернул бы `[1, 1, 5]`: там первой в бюджет попадала пятёрка (она последняя), а шестёрка уже не влезала. Теперь `6` обязательна и занимает место первой, поэтому пятёрке не хватает.

### Задание

Напиши функцию `task_bk22_take_with_required_first(prices, budget)`: цена `prices[0]` обязательна. Если она одна превышает `budget`, верни `[]`. Иначе остальные цены обходи с конца к началу, бери цену, если она влезает вместе с уже взятыми (учитывая обязательную), иначе пропускай. Верни взятые цены, включая `prices[0]`, в исходном порядке.

### Что дальше

Эти четыре задачи (BK19-BK22) готовят тебя к настоящей задаче продукта [XL-A02](task:XL-A02): выбрать сообщения чата для контекста модели в пределах бюджета токенов. Там сообщения соответствуют числам из этой лесенки: токены сообщения - это его «цена», а системное сообщение и последнее сообщение пользователя - обязательный элемент вроде `prices[0]`. Навыки те же: пропустить то, что не влезло, идти от новых сообщений к старым и вернуть выбранные в исходном порядке.

## Аргументы

- `prices` — список целых положительных чисел (может быть пустым).
- `budget` — целое число от 0.

## Возвращает

Список взятых цен в порядке их следования в `prices`; первый элемент — `prices[0]`. Если список пуст или `prices[0] > budget`, то `[]`.

## Правила

- Меняй только тело функции; имя функции и параметры оставь как есть.
- Функция должна **вернуть** значение через `return`, а не печатать его.
- Встроенные `sum`, `max`, `min`, `sorted` не используй. Исходный список не меняй.

## Пример

```python
task_bk22_take_with_required_first([5, 4, 3, 2], 10)   # -> [5, 3, 2]   (5 обязательна; 2 и 3 влезли, 4 нет)
task_bk22_take_with_required_first([6, 1, 1, 5], 10)   # -> [6, 1, 1]
task_bk22_take_with_required_first([11, 1], 10)        # -> []
task_bk22_take_with_required_first([10, 1], 10)        # -> [10]
```

## Учебные цели

- Собрать вместе всё из лесенки: накопитель с начальным значением, пропуск, обход с конца, разворот результата.
- Различать «обязательный» элемент и элементы, которые борются за остаток бюджета.
