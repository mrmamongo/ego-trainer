# Остановиться или пропустить: break и continue рядом

Это главная карточка папки. Одна и та же ситуация: **встретился неподходящий элемент**. Что делать?

- **Остановиться** (`break`): дальше смотреть не нужно, всё остальное нас не интересует.
- **Пропустить** (`continue`): этот элемент не берём, но следующие ещё могут подойти.

## Один и тот же цикл, два поведения

Задача: собрать числа, пока они не больше `5`. Неподходящее — число больше `5`.

```python
def take_stop(numbers):                 # стоп на первом большом
    result = []
    for number in numbers:
        if number > 5:
            break
        result.append(number)
    return result


def take_skip(numbers):                 # пропуск больших
    result = []
    for number in numbers:
        if number > 5:
            continue
        result.append(number)
    return result
```

Единственная разница — одно слово. Вход `[3, 8, 2, 4]`:

| Проход | number | `number > 5`? | `take_stop`: result | `take_skip`: result |
|---|---|---|---|---|
| 1 | 3 | нет | `[3]` | `[3]` |
| 2 | 8 | да | `break`: **конец цикла** | `continue`: `[3]`, идём дальше |
| 3 | 2 | нет | (не смотрели) | `[3, 2]` |
| 4 | 4 | нет | (не смотрели) | `[3, 2, 4]` |

Итог: `take_stop` вернёт `[3]`, а `take_skip` — `[3, 2, 4]`.

## Как выбрать

Задай один вопрос: **«Если этот элемент не подошёл, могут ли подойти те, что дальше?»**

| Ответ | Что делать | Подсказки в условии задачи |
|---|---|---|
| Нет, после него всё теряет смысл | `break` (или `return`) | «до первого…», «пока…», «до стоп-слова», «остановись» |
| Да, остальные не зависят от него | `continue` | «все, кроме…», «пропусти…», «только подходящие», «не учитывай» |

Примеры: сумма «до первого нуля» — стоп. Сумма «всех положительных» — пропуск. Чтение команд «до слова stop» — стоп. Подсчёт «сколько слов длиннее трёх» — пропуск коротких.

## Когда «подходит» зависит от того, что уже набрали

Бывает, что решение «подходит или нет» зависит от накопителя. Например, набираем числа так, чтобы их сумма не превысила лимит `10`, на входе `[4, 8, 3, 2]`:

| Проход | число | сумма с ним | влезает? | со стопом | с пропуском |
|---|---|---|---|---|---|
| 1 | 4 | 4 | да | берём | берём |
| 2 | 8 | 12 | нет | **стоп**, итог `[4]` | пропускаем, сумма так и осталась 4 |
| 3 | 3 | 7 | да | (не смотрели) | берём |
| 4 | 2 | 9 | да | (не смотрели) | берём |

Стоп даёт `[4]`, пропуск — `[4, 3, 2]`. Обрати внимание: после пропуска накопитель **не меняется** (прибавляют только взятое), поэтому следующие числа проверяются по прежней сумме. Эту лесенку мы пройдём шаг за шагом в последних задачах папки (BK19-BK22), а в конце её ждёт настоящая задача продукта [XL-A02](task:XL-A02): там нужно выбрать сообщения чата в пределах бюджета токенов, и решается она ровно этими приёмами.

## Частые ошибки

Взять `break` там, где нужно «пропусти»: цикл молча обрывается, и результат оказывается короче нужного.

```python
for number in numbers:
    if number > 5:
        break               # неверно, если условие «собери все небольшие»
    result.append(number)
```

```python
for number in numbers:
    if number > 5:
        continue            # верно: большие пропускаем, остальные берём
    result.append(number)
```

И наоборот: `continue` там, где нужен стоп, даёт лишние элементы (после стоп-слова цикл продолжает собирать).

## Проверь себя

Что выбрать: `break` или `continue`?

1. «Сложи числа до первого нуля».
2. «Посчитай сумму чисел, кроме отрицательных».
3. «Найди первое число, делящееся на 7».

<details><summary>Ответ</summary>

1. `break` (или `return`): после нуля считать не нужно.
2. `continue`: отрицательное пропускаем, остальные считаем.
3. `break` (или `return`): первое найдено, дальше искать незачем.

</details>
