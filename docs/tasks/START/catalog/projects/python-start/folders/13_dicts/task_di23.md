# Задача DI23: Рейтинг пользователей

## Условие

### Как это работает

Для списка словарей `key` достаёт нужное поле. Чтобы сортировать по нескольким полям, `key` возвращает пару: сначала главное, потом то, что решает при равенстве.

```python
sorted(people, key=lambda person: (-person["age"], person["name"]))
```

Минус перед числом даёт убывание, а имя по алфавиту разрешает ничью. `sorted` создаёт **новый** список: вызывающий код сохраняет свой порядок. Метод `people.sort()` испортил бы чужой список.

### Задание

Напиши функцию `task_di23_sort_users(users)`: верни новый список пользователей, упорядоченный по полю `"level"` от большего к меньшему, а при равных уровнях по `"name"` по алфавиту. Исходный список менять нельзя.

## Аргументы

- `users` — список словарей `{"name": строка, "level": целое}` (может быть пустым).

## Возвращает

Новый список тех же словарей: уровень по убыванию, при равных уровнях имя по алфавиту.

## Правила

- Меняй только тело функции; имя функции и параметры оставь как есть.
- Функция должна **вернуть** значение через `return`, а не печатать его.
- Метод `sort` не используй: список `users` менять нельзя.

## Пример

```python
task_di23_sort_users([{"name": "Боря", "level": 2}, {"name": "Аня", "level": 3}])
# -> [{"name": "Аня", "level": 3}, {"name": "Боря", "level": 2}]
task_di23_sort_users([])   # -> []
```

## Учебные цели

- Сортировать список словарей по двум полям.
- Не менять входной список: использовать `sorted`, а не `sort`.

## Проверка понимания

Что вернёт функция для пустого списка? Чем плох `users.sort(...)` для чужого списка?
