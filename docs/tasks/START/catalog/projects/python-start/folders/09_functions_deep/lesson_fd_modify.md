# Как менять готовую функцию под новое требование

Это главная карточка папки. В работе чаще пишут не новый код с нуля, а **правят существующий**: «раньше функция делала так, а теперь должна вот так». Главная опасность — сломать то, что уже работало и до сих пор нужно.

## Пять шагов

1. **Прочитай старый код** и пойми, что он делает. Не переписывай, пока не понял.
2. **Пройди по нему на примере** (таблица по проходам или по ветвям). Так видно, откуда берётся ответ.
3. **Найди одно место, где реализовано старое правило.** Это строка, ветка или число, которое отвечает за то, что меняется.
4. **Измени только его.** Остальное не трогай: оно держит старое поведение.
5. **Перепроверь старые и новые случаи.** Старые примеры должны дать прежние ответы (если условие не говорит обратное), новые — новые.

## Пример

Раньше: скидка 10% для заказа от 1000. Теперь: от 5000 скидка 20%.

```python
def discount(price):               # 1
    if price >= 1000:              # 2: старое правило «от 1000»
        return price - price * 10 // 100   # 3
    return price                   # 4
```

Шаг 2. Трассировка:

| price | какая строка вернула | ответ |
|---|---|---|
| 500 | 4 | 500 |
| 2000 | 3 | 1800 |

Шаг 3. Старое правило живёт в строках 2–3. Новому правилу нужна **новая ветка**. Куда её поставить? **Перед** старой: иначе число 6000 тоже подходит под `>= 1000`, и до новой ветки дело не дойдёт.

```python
def discount(price):
    if price >= 5000:                      # новая ветка: стоит первой
        return price - price * 20 // 100
    if price >= 1000:                      # старая ветка не тронута
        return price - price * 10 // 100
    return price
```

Шаг 5. Проверка: `500` → `500` (старый случай), `2000` → `1800` (старый), `6000` → `4800` (новый). Граница `5000` → `4000`, а `4999` → `4500`.

## Какой бывает правка

| Что меняется | Что делать |
|---|---|
| одно слово или число (`break` → `continue`) | поменять только его |
| появилось новое условие | добавить ветку (обычно перед старыми) |
| нужен ещё один входной параметр | добавить параметр **со значением по умолчанию**, чтобы старые вызовы работали |
| кусок кода стал слишком большим или нужен в двух местах | вынести в отдельную функцию-помощник и вызывать её |

Чем меньше правка, тем меньше шансов сломать старое.

## Частые ошибки

Переписать функцию с нуля «как мне проще». Новый код теряет мелкие детали старого: граничные случаи, порядок, обработку пустого списка.

Поменять код и проверить **только новый** случай. Старые примеры надо прогнать обязательно: именно они ловят поломку.

Поставить новую ветку после старой, которая подходит и под новые данные: она никогда не сработает.

## Проверь себя

Старый код:

```python
def first_big(numbers):
    for n in numbers:
        if n > 10:
            return n
    return 0
```

Новое требование: теперь нужно вернуть **не число, а его номер** в списке (с нуля), а если больших нет — `-1`.

1. Какие места старого кода реализуют старое правило «первое большое»?
2. Что нужно оставить как есть?

<details><summary>Ответ</summary>

1. Старое правило «что считать большим» живёт в условии `n > 10` — его не трогаем. Меняется то, **что возвращаем**: `return n` и `return 0`. Чтобы получить номер, цикл удобнее вести по `range(len(numbers))`.
2. Остаются: порядок просмотра слева направо, условие `> 10`, ранний `return` на первом найденном.

</details>
