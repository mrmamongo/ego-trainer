# Задача FD07: НДС по ставке

## Условие

### Как это работает

Сейчас функция всегда прибавляет НДС 20%. Вот она:

```python
def task_fd07_price_with_vat(price):             # 1
    return price + price * 20 // 100             # 2
```

**Где реализовано старое правило:** в строке 2 это число `20`. Выражение `price * 20 // 100` считает 20% от цены, и результат прибавляется к цене. Для `price = 100` получается `120`.

**Что меняется:** ставка больше не должна быть зашита в код. Число `20` заменяем на новый параметр `rate` (строка 2), а параметр добавляем в заголовок (строка 1).

**Что нельзя сломать:** в других местах уже есть вызовы `task_fd07_price_with_vat(100)` с одним аргументом. Поэтому у `rate` должно быть значение по умолчанию `20`: тогда старый вызов даёт прежний ответ (урок `fd-defaults`).

### Задание

Раньше функция принимала только цену и всегда прибавляла 20%. Теперь она должна принимать вторым параметром ставку `rate` в процентах.
Если ставку не передали, должно считаться по ставке 20, как раньше. Измени готовую функцию, не пиши её с нуля.

## Аргументы

- `price` — целая цена, не меньше `0`.
- `rate` — целая ставка в процентах, не меньше `0`; необязательный, по умолчанию `20`.

## Возвращает

Целое число: `price + price * rate // 100`.

## Правила

- Измени готовый код: добавь параметр и подставь его вместо числа `20`.
- Вызов с одним аргументом должен давать прежний результат.
- Функция должна **вернуть** значение через `return`, а не печатать его.

## Пример

```python
task_fd07_price_with_vat(100)        # -> 120 (как раньше)
task_fd07_price_with_vat(100, 10)    # -> 110
task_fd07_price_with_vat(200, 0)     # -> 200
```

## Учебные цели

- Добавить параметр к готовой функции, не сломав старые вызовы.
- Находить в коде место, где «зашито» число, ставшее параметром.

## Проверка понимания

Что случится со старым вызовом `task_fd07_price_with_vat(100)`, если написать `rate` без значения по умолчанию? Почему вызов `(100, 10)` даёт `110`?
