# Список изменяем: b = a не копия

Это главная карточка папки. Из неё вытекает правило, которое пригодится в каждой настоящей задаче: **функция не должна портить список, который ей передали.**

## Число копируется, список — нет

В карточке про `q = p` числа копировались: после `q = p` два имени держат два независимых значения. Со списками иначе.

**Переменная со списком — это ярлык на коробке.** Сам список лежит в памяти один, а имя лишь указывает на него. Строка `b = a` не делает второй список, она вешает на ту же коробку **второй ярлык**.

```python
a = [1, 2]          # 1
b = a               # 2
b.append(3)         # 3
c = a[:]            # 4
c.append(4)         # 5
a[0] = 9            # 6
```

| После строки | a | b | c | Сколько списков |
|---|---|---|---|---|
| 1 | `[1, 2]` | — | — | 1 |
| 2 | `[1, 2]` | тот же список | — | 1 (у него два имени) |
| 3 | `[1, 2, 3]` | `[1, 2, 3]` | — | 1 |
| 4 | `[1, 2, 3]` | `[1, 2, 3]` | `[1, 2, 3]` | 2 (`c` — новый) |
| 5 | `[1, 2, 3]` | `[1, 2, 3]` | `[1, 2, 3, 4]` | 2 |
| 6 | `[9, 2, 3]` | `[9, 2, 3]` | `[1, 2, 3, 4]` | 2 |

Через `b` изменили «общую коробку», а `a` увидел это, потому что `a` и `b` — один и тот же список. А `c` получился срезом, то есть **копией**, и на него изменения `a` и `b` не влияют.

## Как сделать копию

- `a[:]` — срез всего списка;
- `list(a)` — то же самое, новый список с теми же элементами.

А вот `b = a` копией **не** является.

## Функция тоже получает ярлык

Когда список передают в функцию, параметр становится ещё одним именем на тот же список. Всё, что функция сделает с параметром методами (`append`, `sort`, `remove`) или присваиванием `nums[0] = ...`, произойдёт и в списке вызывающего кода.

```python
def add_zero(nums):
    nums.append(0)

data = [5, 6]
add_zero(data)
# data теперь [5, 6, 0]: функция изменила чужой список
```

Сравни с функцией, которая **не меняет** вход и возвращает новый список:

```python
def with_zero(nums):
    result = nums[:]     # копия
    result.append(0)
    return result

data = [5, 6]
longer = with_zero(data)
# data остался [5, 6], longer равен [5, 6, 0]
```

| Стиль | Что делает с `data` | Что возвращает |
|---|---|---|
| менять на месте (`add_zero`) | меняет | `None` |
| вернуть новый (`with_zero`) | не трогает | новый список |

## Правило по умолчанию

**Если в условии прямо не сказано «измени список», не трогай входной список и верни новый.** Так вызывающий код не получит сюрприз: его данные остались такими, как были. Проверка в этой папке именно это и контролирует: она сравнивает аргументы до и после вызова.

Чтобы не изменить вход, не вызывай на параметре `append`, `sort`, `remove`, `pop`, `insert`, `reverse` и не присваивай `nums[i] = ...`. Сначала сделай копию (`result = nums[:]`) или собери результат с нуля (`result = []`), и работай с ним.

## Частые ошибки

Считать, что `copy = nums` делает копию:

```python
def sorted_copy(nums):
    copy = nums          # неверно: это второй ярлык на тот же список
    copy.sort()          # отсортировали и копию, и nums
    return copy
```

```python
    copy = nums[:]       # верно: новый список
```

Вернуть изменённый параметр вместо нового списка: результат правильный, но у вызывающего кода пропали исходные данные.

## Проверь себя

```python
a = [1, 2, 3]
b = a
c = list(a)
b[0] = 7
```

1. Чему равны `a`, `b`, `c`?
2. Изменит ли чужой список функция `def f(nums): return nums[:2]`?

<details><summary>Ответ</summary>

1. `a` и `b` — один список, оба равны `[7, 2, 3]`. `c` — копия, она осталась `[1, 2, 3]`.
2. Нет: срез создаёт новый список, а `nums` она только читает.

</details>
