# Знак = — это команда записи

**Переменная** — это имя, под которым программа помнит **одно** значение.

Строка `x = 5` читается не «x равно 5», а как **команда**: «запиши 5 под именем `x`».
Слева от `=` всегда имя, справа — то, что записываем.

## Как программа идёт по строкам

Строки выполняются **сверху вниз, по одной**. Каждая строка работает с тем, что осталось после предыдущей.
Если под именем уже было значение, новое присваивание **стирает старое**: в каждый момент у переменной ровно одно значение.

## Таблица трассировки

Чтобы не запутаться, ведут таблицу: строка кода → значения переменных **после** неё.

```python
x = 5    # 1
y = 3    # 2
x = 8    # 3
```

| После строки | x | y |
|---|---|---|
| 1 | 5 | — |
| 2 | 5 | 3 |
| 3 | 8 | 3 |

«—» значит, что такой переменной ещё нет. На строке 3 изменился только `x`; `y` никто не трогал, поэтому он остался прежним.

**Порядок строк важен.** Те же строки в другом порядке могут дать другой результат:

```python
n = 4        # 1       m = 4        # 1
n = n + 1    # 2       m = m * 2    # 2
n = n * 2    # 3       m = m + 1    # 3
```

Слева получится `n = 10` (сначала +1, потом ×2), справа `m = 9` (сначала ×2, потом +1).

## Частые ошибки

Читать `=` как равенство и думать, что «после неё всё равно друг другу навсегда»:

```python
# неверно: «x равно 5, значит, он всегда 5»
x = 5
x = 8       # теперь x равно 8, а пятёрки больше нет
```

Правильно: каждая строка — отдельный шаг, а в таблице у переменной хранится последнее записанное значение.

## Проверь себя

1. Что будет в `a` и `b` после строк `a = 2`, `b = 3`, `a = 7`? Подумай, потом проверь по таблице.
2. Что будет в `n` после `n = 1`, `n = 10`?

<details><summary>Ответ</summary>

1. После строки 1 `a = 2`, после строки 2 `b = 3`. Строка 3 меняет только `a`, поэтому `a = 7`, `b = 3`.
2. Вторая строка стёрла первую, поэтому `n = 10`.

</details>
