# Задача L02: Накопитель

## Условие

### Как это работает

Часто в цикле нужно что-то **накапливать**: сумму цен, общую длину, итог. Для этого заводят переменную-**накопитель** с именем `total`:
до цикла она получает начальное значение, а на каждом проходе к ней прибавляют очередной элемент.

```python
total = 0                   # 1
for price in [4, 6]:        # 2
    total = total + price   # 3
```

| Проход | price | total после тела |
|---|---|---|
| 1 | 4 | 4 |
| 2 | 6 | 10 |

Справа считается `total + price` по **старому** `total`, потом результат записывается обратно (как в `n = n + 1` из первой папки).

**Паспорт роли «накопитель»** (имя `total`):

| Где заводим | Начальное значение | Как меняем в теле | Когда возвращаем |
|---|---|---|---|
| до цикла | `0` | `total = total + item` | после цикла |

Правило: **начальное значение — это ответ для пустого списка.** Если список пуст, тело не выполнится ни разу, и сумма останется `0`.
Именно поэтому для суммы начинаем с `0`.

### Задание

Открой файл задачи. В нём код для трассировки и строчки-ответы с `None`.
Впиши вместо каждого `None` ответ. `total_after_iter_1`, `total_after_iter_2`, `total_after_iter_3` — значение `total` после тела цикла на каждом проходе, `total_final` — после всего цикла.

**Сначала реши в голове или на бумаге, код не запускай.** Цель — научиться видеть,
что происходит, без компьютера. Если ответ неверный, проверка не подскажет правильный:
найди ошибку сам, построив таблицу по проходам цикла.

## Правила

- Меняй только строчки с `None`.
- Строки `def task_l02_trace():` и `return ...` самой рамки не трогай: так проверка читает твои ответы.

## Учебные цели

- Видеть, как накопитель растёт от прохода к проходу.
- Связывать начальное значение накопителя с ответом для пустого списка.

## Проверка понимания

Чему равен `total` после цикла, если список пуст? Почему для суммы начинают с `0`, а не с `1`?
