# Задача L15: Есть ли отрицательное

## Условие

### Как это работает

Когда ответ — «да» или «нет», удобно завести **флаг**: переменную-bool, которая сначала говорит «пока не нашли»,
а в теле цикла меняется на «нашли».

```python
def has_big(numbers):
    found = False
    for number in numbers:
        if number > 100:
            found = True
    return found
```

**Паспорт роли «флаг»** (имя `found`; для вариантов «все ли…» — `all_ok`):

| Где заводим | Начальное значение | Как меняем в теле | Когда возвращаем |
|---|---|---|---|
| до цикла | `False` | `found = True` — когда нашли | после цикла |

Начальное значение — ответ для пустого списка: искать негде, значит, «не нашли».

Есть и другой верный способ: выйти сразу при находке — `return True` внутри `if`, а после цикла `return False`. Оба варианта правильные.

### Задание

Напиши функцию `task_l15_has_negative(numbers)`: верни `True`, если в списке есть хотя бы одно отрицательное число, иначе `False`.

## Аргументы

- `numbers` — список целых чисел (может быть пустым).

## Возвращает

`True` или `False`.

## Правила

- Меняй только тело функции; имя функции и параметры оставь как есть.
- Функция должна **вернуть** значение через `return`, а не печатать его.

## Пример

```python
task_l15_has_negative([1, -2, 3])   # -> True
task_l15_has_negative([1, 2, 3])    # -> False
task_l15_has_negative([])           # -> False
```

## Учебные цели

- Применять флаг: `False` до цикла, `True` при находке.
- Знать про альтернативу — ранний `return`.

## Проверка понимания

Что вернёт функция для `[0]`? Почему в цикле нельзя написать `found = False` в ветке `else`?
