# Задача ER08: Проверка заказа: первая ошибка в фиксированном порядке

## Условие

### Как это работает

Когда у данных несколько проблем сразу, функция должна называть **одну и ту же** — первую в договорённом порядке. Для этого проверки ставят цепочкой `if … return`, и каждая следующая выполняется, только если предыдущие прошли:

```python
def check_item(item):
    if item["qty"] < 1:
        return "bad_qty"
    if item["price"] < 0:
        return "bad_price"
    return "ok"
```

| `qty` | `price` | Что вернёт |
|---|---|---|
| `2` | `5` | `"ok"` |
| `0` | `5` | `"bad_qty"` |
| `0` | `-1` | `"bad_qty"`: первая сработавшая проверка определяет ответ |

Если проверка касается **всех** позиций заказа, она идёт циклом по ним целиком и только потом начинается следующая проверка. Заказ с неверным количеством в последней позиции и неизвестным товаром в первой получает `"bad_qty"`: он идёт раньше `"unknown_item"` в порядке проверок.

Цены известны заранее: словарь `PRICES` уже записан в файле задачи (товары и цена за штуку).

### Задание

Напиши функцию `task_er08_validate_order(order)`. Заказ — словарь `{"items": [{"name": ..., "qty": ...}, ...], "budget": ...}`. Функция возвращает `"ok"`, если заказ в порядке, иначе **код первой сработавшей проверки** в таком порядке:

1. `"no_items"` — список позиций пуст;
2. `"bad_qty"` — у какой-нибудь позиции `qty` не целое число или меньше `1`;
3. `"unknown_item"` — у какой-нибудь позиции `name` нет в `PRICES`;
4. `"over_budget"` — сумма `PRICES[name] * qty` по всем позициям больше `budget`.

## Аргументы

- `order` — словарь с ключами `"items"` (список позиций, может быть пустым) и `"budget"` (целое число).

## Возвращает

Строку: `"ok"` или один из кодов `"no_items"`, `"bad_qty"`, `"unknown_item"`, `"over_budget"`.

## Правила

- Порядок проверок как в условии. Новых кодов не добавляй.
- Заказ не меняй.
- `try`/`except` не используй: все проверки делаются обычными условиями.
- Функция должна **вернуть** значение через `return`, а не печатать его.

## Пример

```python
order = {"items": [{"name": "чай", "qty": 2}], "budget": 300}
task_er08_validate_order(order)    # -> "ok" (2 * 50 = 100, это не больше 300)

task_er08_validate_order({"items": [], "budget": 0})    # -> "no_items"
task_er08_validate_order({"items": [{"name": "чай", "qty": 0}], "budget": 100})    # -> "bad_qty"
```

## Учебные цели

- Ставить проверки в фиксированном порядке и возвращать первую сработавшую.
- Не обращаться к данным раньше, чем проверено, что они есть.

## Проверка понимания

Что вернёт заказ с одной позицией `{"name": "суп", "qty": 0}` при любом бюджете? Почему не `"unknown_item"`?
