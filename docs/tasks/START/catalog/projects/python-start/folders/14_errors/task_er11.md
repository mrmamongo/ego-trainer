# Задача ER11: Список команд: ошибка одной строки не роняет остальные

## Условие

### Как это работает

Когда обрабатываешь много строк, одна плохая не должна останавливать остальные. Для этого `try` ставят **внутрь цикла**, вокруг обработки одной строки (как в задаче ER02), а результат строки кладут в список:

```python
def to_numbers(texts):
    results = []
    for text in texts:
        try:
            results.append(int(text))
        except ValueError:
            results.append("bad")
    return results
```

| Вход | Результат |
|---|---|
| `["4", "x", "6"]` | `[4, "bad", 6]` |
| `[]` | `[]` |

Каждая строка даёт ровно один элемент результата: либо значение, либо код ошибки. Поэтому результат по длине равен списку команд.

Команду разбирают через `split()` (урок `px-parsing`): первое слово — название, второе — аргумент.

### Задание

Напиши функцию `task_er11_process_lines(lines)`. Она выполняет команды над числом `total`, которое в начале равно `0`:

- `add N` — прибавить `N` к `total`;
- `sub N` — вычесть `N` из `total`.

Для каждой строки в результат попадает **новое значение `total`** или **код ошибки**. Проверки идут в таком порядке:

1. `"unknown_command"` — строка пуста или её первое слово не `add` и не `sub` (регистр важен);
2. `"bad_number"` — слов не два, или второе слово не целое число, или число отрицательное;
3. `"not_enough"` — для `sub`: `N` больше текущего `total`.

Строка с ошибкой `total` не меняет.

## Аргументы

- `lines` — список строк-команд (может быть пустым).

## Возвращает

Список той же длины, что `lines`: на каждой позиции целое число (новый `total`) или одна из строк `"unknown_command"`, `"bad_number"`, `"not_enough"`.

## Правила

- Преобразуй число через `int(...)` и лови ошибку через `try`/`except ValueError`; метод `isdigit` не используй.
- Одна плохая строка не должна прерывать обработку остальных.
- Входной список не меняй.
- Функция должна **вернуть** значение через `return`, а не печатать его.

## Пример

```python
task_er11_process_lines(["add 5", "sub x", "add 3"])   # -> [5, "bad_number", 8]
task_er11_process_lines(["mul 2", "sub 1"])            # -> ["unknown_command", "not_enough"]
task_er11_process_lines([])                            # -> []
```

## Учебные цели

- Ставить `try` внутрь цикла, вокруг обработки одного элемента.
- Возвращать результат для каждой строки, включая ошибочные.

## Проверка понимания

Почему для `["add 5", "sub x", "add 3"]` итог равен `8`, а не `5`? Что случилось бы, если поставить `try` вокруг всего цикла?
