# Задача ER07: Куда всплывёт ошибка

## Условие

### Как это работает

Если функция не поймала исключение, оно **всплывает** к тому, кто её вызвал, и так далее вверх по цепочке вызовов. Каждый `try` по пути проверяет: «мой `except` подходит по типу?». Если подходит, ошибка поймана здесь; если нет, она летит дальше.

```python
def inner(x):                    # 1
    return 10 // x               # 2: при x = 0 бросает ZeroDivisionError

def outer(x):                    # 4
    try:                         # 5
        return inner(x) + 1      # 6
    except ZeroDivisionError:    # 7
        return -2                # 8
```

`outer(0)`: ошибка возникла в `inner`, там её никто не ловит, она всплыла в `outer`, и его `except ZeroDivisionError` подошёл. Ответ `-2`.
Если бы в `outer` стоял `except KeyError`, тип не подошёл бы, и ошибка вылетела бы наружу.

Когда ошибка поймана, строки после неё в `try` не выполняются, а функция, где она случилась, не вернёт ничего.

### Задание

Открой файл задачи. В нём три функции, вызывающие друг друга, и три вызова. Впиши вместо каждого `None` ответ: `a_value`, `b_value`, `c_value` — что вернул каждый вызов `outer`, `b_caught_in` — имя функции (`"inner"`, `"middle"` или `"outer"`), в которой поймана ошибка второго вызова.

**Сначала реши в голове или на бумаге, код не запускай.** Для `outer(0)` пройди по цепочке вверх и на каждом шаге проверь тип в `except`.

## Правила

- Меняй только строчки с `None`.
- Строки `def task_er07_trace():` и `return ...` самой рамки не трогай: так проверка читает твои ответы.

## Учебные цели

- Следить за тем, как исключение поднимается по цепочке вызовов.
- Сравнивать тип ошибки с типом в `except`.

## Проверка понимания

Почему `except KeyError` в `middle` не поймал `ZeroDivisionError`? Что бы вернул `outer(0)`, если бы в `outer` вообще не было `try`?
