# Задача ER03: Безопасное преобразование в число

## Условие

### Как это работает

`int("42")` даёт `42`, а `int("abc")` бросает `ValueError`. Чтобы программа не падала, опасную строку кладут в `try`, а ожидаемую ошибку ловят **по имени типа**:

```python
def to_level(text):
    try:
        return int(text)
    except ValueError:
        return 1
```

| Вызов | Что произойдёт |
|---|---|
| `to_level("5")` | `int` отработал, вернулось `5` |
| `to_level("abc")` | `int` бросил `ValueError`, сработал `except`, вернулась `1` |

Заметь: `"-7".isdigit()` равно `False`, хотя `-7` вполне число. `int` понимает и минус, и пробелы по краям (`int(" 12 ")` равно `12`), поэтому проверять через `try` надёжнее, чем перебирать символы.

### Задание

Напиши функцию `task_er03_safe_int(text, default)`: она возвращает `int(text)`, а если `text` не получается превратить в целое число, возвращает `default`.

## Аргументы

- `text` — строка (может быть пустой, с пробелами по краям, с минусом, дробной).
- `default` — значение, которое вернуть при неудаче (любое).

## Возвращает

Целое число `int(text)`; если так нельзя — `default`.

## Правила

- Используй `try` и `except ValueError`. Метод `isdigit` не используй.
- Ловить нужно именно `ValueError`, а не любую ошибку.
- Функция должна **вернуть** значение через `return`, а не печатать его.

## Пример

```python
task_er03_safe_int("42", 0)     # -> 42
task_er03_safe_int("abc", 0)    # -> 0
task_er03_safe_int("-7", 5)     # -> -7
task_er03_safe_int("4.5", -1)   # -> -1
```

## Учебные цели

- Оборачивать опасное преобразование в `try` с конкретным типом ошибки.
- Возвращать значение по умолчанию вместо падения.

## Проверка понимания

Почему `"4.5"` даёт `default`, хотя это число? Что изменится, если вместо `except ValueError` написать голый `except:`?
