# Исключение и traceback: читаем ошибку снизу вверх

Когда Python не может выполнить строку, он **бросает исключение**: останавливает программу и печатает отчёт об ошибке — **traceback**. Ты уже встречал такие ошибки: `ValueError`, `KeyError`, `IndexError`, `TypeError`, `ZeroDivisionError`, `NameError`. Теперь научимся их читать и управлять ими.

```python
def price_with_tax(price, rate):         # строка 1
    return price + price // rate         # строка 2

def total(prices, rate):                 # строка 4
    result = 0                           # строка 5
    for price in prices:                 # строка 6
        result = result + price_with_tax(price, rate)   # строка 7
    return result                        # строка 8

total([100, 200], 0)                     # строка 10
```

```text
Traceback (most recent call last):
  File "demo.py", line 10, in <module>
    total([100, 200], 0)
  File "demo.py", line 7, in total
    result = result + price_with_tax(price, rate)
  File "demo.py", line 2, in price_with_tax
    return price + price // rate
ZeroDivisionError: integer division or modulo by zero
```

## Как читать

**Снизу вверх.** Самая нижняя строка — главное: `ТипОшибки: сообщение`. Над ней — строка кода, где всё сломалось (строка 2). Выше — цепочка вызовов: кто вызвал эту функцию (`total`, строка 7), кто вызвал её (строка 10). Цепочку читают, чтобы понять, **с какими данными** функцию вызвали.

| Тип | Что значит | Пример |
|---|---|---|
| `ValueError` | значение неподходящее | `int("abc")` |
| `TypeError` | неподходящий тип | `"5" + 1` |
| `KeyError` | нет такого ключа | `{"a": 1}["b"]` |
| `IndexError` | нет такого номера | `[1, 2][5]` |
| `ZeroDivisionError` | деление на ноль | `10 // 0` |
| `NameError` | имя не заведено (часто опечатка) | `totl + 1` |

Тип ошибки уже говорит, в чём беда; сообщение уточняет детали.

## Исключение «всплывает»

Если в функции ошибку никто не поймал, она **всплывает** к тому, кто функцию вызвал, потом выше, и так до самого верха. Если не поймал никто — программа останавливается. Что значит «поймать», расскажет следующая карточка.

## Частые ошибки

Читать traceback сверху и искать причину в первой строке: там только «с чего всё началось», а не «что сломалось».

Считать, что сообщение об ошибке всегда указывает на виноватую строку. `NameError` из-за опечатки показывает именно ту строку, где опечатка, но `ValueError` может прийти из данных, которые подготовили раньше.

## Проверь себя

```python
numbers = [4, 0, 5]
print(100 // numbers[1])
print(numbers[3])
```

1. Какая ошибка случится и на какой строке?
2. Дойдёт ли дело до второго `print`?

<details><summary>Ответ</summary>

1. На первом `print`: `ZeroDivisionError`, потому что `numbers[1]` равно `0`.
2. Нет: программа остановится на первой ошибке. (Второй `print` дал бы `IndexError`: в списке всего три элемента.)

</details>
