# Задача ER13: Действие с кодом отказа

## Условие

### Как это работает

В продуктовых задачах функция, которая выполняет действие, всегда отвечает словарём одной формы (урок `er-codes`):

| Поле | При успехе | При отказе |
|---|---|---|
| `status` | `"done"` | `"rejected"` |
| `state` | **новое** состояние | **исходное** состояние |
| `result` | что получилось | `None` |
| `reason` | `None` | код отказа |

Главное правило: **сначала проверки, потом изменения**. Пока хоть одна проверка не прошла, состояние трогать нельзя, иначе отказ испортит данные. Успешный ответ собирают из **новых** значений, а не правят пришедшие:

```python
def use_potion(state):
    if state["potions"] == 0:
        return {"status": "rejected", "state": state, "result": None, "reason": "no_potions"}
    new_state = {"potions": state["potions"] - 1}     # новый словарь, state не тронут
    return {"status": "done", "state": new_state, "result": {"left": new_state["potions"]}, "reason": None}
```

Готовый помощник `given_rejected(state, reason)` из файла задачи собирает ответ-отказ; его менять не нужно.

### Задание

Состояние игрока — словарь `{"gold": int, "items": [названия]}`. Напиши функцию `task_er13_apply_action(state, action)`. Действие — словарь с ключом `"tool"`:

- `{"tool": "buy", "item": ..., "price": ...}` — купить предмет. Проверки в таком порядке: `"bad_price"` (цена не целое число или не больше нуля), `"already_owned"` (предмет уже в `items`), `"not_enough_gold"` (цена больше `gold`). Успех: `gold` уменьшается на цену, предмет добавляется в конец `items`, `result` равен `{"item": предмет}`.
- `{"tool": "drop", "item": ...}` — выбросить предмет. Отказ `"not_owned"`, если предмета нет. Успех: предмет убран из `items`, `gold` прежний, `result` равен `{"item": предмет}`.
- любой другой `tool` — отказ `"unknown_tool"`.

### Что дальше

Такой же формат ответа и порядок кодов отказа ты встретишь в продуктовой задаче [XL-A14](task:XL-A14). Там главное не перепутать отказ с успехом.

## Аргументы

- `state` — словарь `{"gold": целое число, "items": список строк}`.
- `action` — словарь действия; у `buy` есть `item` и `price`, у `drop` есть `item`.

## Возвращает

Словарь `{"status", "state", "result", "reason"}` как в таблице выше.

## Правила

- Входные `state` и `action` не меняй: в успешном ответе возвращай новый словарь и новый список.
- При отказе возвращай исходный `state` без изменений (удобно через `given_rejected`).
- Порядок проверок как в условии.
- Функция должна **вернуть** значение через `return`, а не печатать его.

## Пример

```python
state = {"gold": 100, "items": ["меч"]}
task_er13_apply_action(state, {"tool": "buy", "item": "щит", "price": 30})
# -> {"status": "done", "state": {"gold": 70, "items": ["меч", "щит"]},
#     "result": {"item": "щит"}, "reason": None}
task_er13_apply_action(state, {"tool": "buy", "item": "меч", "price": 30})
# -> {"status": "rejected", "state": state, "result": None, "reason": "already_owned"}
```

## Учебные цели

- Возвращать ответ единой формы `{status, state, result, reason}`.
- Проверять до изменений и не портить исходное состояние при отказе.
