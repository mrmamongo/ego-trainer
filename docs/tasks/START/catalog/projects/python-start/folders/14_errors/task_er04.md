# Задача ER04: Голый except прячет опечатку

## Условие

### Как это работает

Голый `except:` (без типа) ловит **любую** ошибку, в том числе ту, которой ты не ждал. Тогда настоящая поломка превращается в «обычный» ответ по умолчанию, и найти её очень трудно:

```python
def read_cents(text, default):
    try:
        rubles = int(text)
        return rubls * 100      # опечатка в имени: NameError
    except:
        return default
```

| Вызов | Что ожидали | Что вернулось |
|---|---|---|
| `read_cents("5", -1)` | `500` | `-1`: `NameError` проглочен |
| `read_cents("abc", -1)` | `-1` | `-1` |

Для «плохого» текста функция вернула правильное значение, а для хорошего — неправильное, и никакого сообщения об ошибке. С `except ValueError:` опечатка сразу бы упала с `NameError` и была бы исправлена за минуту.

Для проверки ошибок в этом файле есть помощник `given_capture(fn, *args)`: он вызывает функцию и либо возвращает результат, либо `["error", "ТипОшибки", "сообщение"]`. Его не меняй.

### Задание

Функция `read_cents(text, default)` должна переводить рубли из текста в копейки (`"5"` -> `500`). Для текста, который не является целым числом, она возвращает `default`. Сейчас она ошибается на любых данных. Найди **две** ошибки: опечатку в имени и слишком широкий `except`. Исправь обе.

Функция `task_er04_cents` вызывает `read_cents` через `given_capture`: так тесты видят и результат, и неожиданную ошибку.

## Аргументы

- `text` — строка или другое значение (например, `None`).
- `default` — что вернуть, если `text` не целое число.

## Возвращает

Целое число копеек `int(text) * 100`; если `text` — строка, но не целое число, — `default`. Если пришло не строка и не число (например, `None`), ошибку нельзя прятать: она должна дойти до `given_capture`.

## Правила

- Меняй только функцию `read_cents`.
- Ловить нужно только `ValueError`.
- Функция должна **вернуть** значение через `return`, а не печатать его.

## Пример

```python
task_er04_cents("5", -1)       # -> 500
task_er04_cents("abc", -1)     # -> -1
```

## Учебные цели

- Понимать, что голый `except:` скрывает баги.
- Ловить конкретный тип ошибки.

## Проверка понимания

Почему исходная функция для `"5"` возвращает `-1`? Что случится с `None` на входе, когда ты исправишь `except`, и почему это хорошо?
