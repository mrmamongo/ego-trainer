# Порядок проверок и охранные if…return

Проверок у данных обычно несколько. Если они все провалены одновременно, ответ должен быть **один и тот же всегда**. Для этого проверки идут в **фиксированном порядке**, а ответом становится **первая сработавшая**.

```python
def validate_age(age):
    if age is None:
        return "missing"
    if age < 0:
        return "negative"
    if age > 150:
        return "too_big"
    return "ok"
```

## Охранные условия (guard clauses)

Каждая строка `if … return` в начале функции «охраняет» основную работу: пока не пройдены все проверки, до неё дело не дойдёт. Это плоско и читаемо:

```python
def final_price(price, percent):
    if price < 0:
        return "bad_price"
    if percent < 0 or percent > 100:
        return "bad_percent"
    return price - price * percent // 100      # основная работа, когда всё проверено
```

Без охраны получается лесенка из вложенных `if`, а основная работа тонет в отступах.

## Порядок решает

Проверки зависят друг от друга: одну можно делать только после другой.

```python
def check(items):
    if len(items) == 0:        # 1: сначала «есть ли что проверять»
        return "no_items"
    if items[0] < 0:           # 2: иначе items[0] упадёт на пустом списке
        return "bad_first"
    return "ok"
```

И даже когда проверки независимы, порядок определяет **какой код увидит пользователь**. Для `[]` и `[-1]` ответы разные только потому, что проверка 1 стоит раньше проверки 2.

| Правило | Зачем |
|---|---|
| сначала проверки, без которых остальные упадут | `no_items` перед обращением к элементам |
| дальше то, что дешевле и очевиднее | формат, потом смысл |
| в конце дорогие и составные проверки | бюджет, сумма |

Если в условии задачи есть порядок кодов, **выполняй его буквально**. Новую проверку нужно вставлять не «в конец», а на то место, которое задал порядок.

## Частые ошибки

Поставить обращение к данным раньше проверки, что они есть (`items[0]` до `len(items)`).

Вставить новую проверку в конец, хотя по смыслу она должна идти раньше: тогда другая проверка «перехватит» ответ.

Забыть про `return`: проверка нашла ошибку, но функция пошла дальше.

## Проверь себя

```python
def check(order):
    if order["qty"] < 1:
        return "bad_qty"
    if order["price"] < 0:
        return "bad_price"
    return "ok"
```

1. Что вернёт `check({"qty": 0, "price": -5})`?
2. Что изменится, если поменять `if` местами?

<details><summary>Ответ</summary>

1. `"bad_qty"`: первая сработавшая проверка определяет ответ.
2. Тот же заказ получит `"bad_price"`. Данные те же, а ответ другой — поэтому порядок надо держать как в условии.

</details>
