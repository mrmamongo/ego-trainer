# Задача ER09: Новая проверка: повторяющийся товар

## Условие

### Как это работает

Сейчас проверка заказа работает так (это решение предыдущей задачи):

```python
def task_er09_validate_order(order):
    items = order["items"]
    if len(items) == 0:                       # 1: no_items
        return "no_items"
    for item in items:                        # 2: bad_qty
        if type(item["qty"]) is not int or item["qty"] < 1:
            return "bad_qty"
    for item in items:                        # 3: unknown_item
        if item["name"] not in PRICES:
            return "unknown_item"
    ...                                       # 4: over_budget
```

Правило «первая сработавшая проверка определяет ответ» значит, что **место** новой проверки в цепочке влияет на результат. Пятый шаг урока `fd-modify`: старые случаи должны дать старые ответы, новый случай — новый.

Новая проверка `"duplicate_item"` — один и тот же товар записан в заказе дважды. Её место — **сразу после `no_items`**, до всех остальных. Почему не в конце:

| Заказ | Если проверка в конце | Если сразу после `no_items` |
|---|---|---|
| `чай x1, чай x1`, бюджет 1 | `over_budget` | `duplicate_item` |
| `чай x0, чай x1` | `bad_qty` | `duplicate_item` |
| `суп x1, суп x1` | `unknown_item` | `duplicate_item` |

Заказ с повторами — ошибка самого заказа, а не отдельной позиции, и пользователь должен исправить её первой: количества и суммы по такому заказу всё равно придётся пересчитывать. Поэтому структура заказа проверяется раньше содержимого позиций.

Заметь также, что пустой заказ повторов иметь не может, так что `no_items` по-прежнему идёт первым.

### Задание

Раньше функция проверяла заказ в порядке `no_items`, `bad_qty`, `unknown_item`, `over_budget`. Теперь порядок такой: `no_items`, **`duplicate_item`**, `bad_qty`, `unknown_item`, `over_budget`. `duplicate_item` возвращается, если какое-то `name` встречается в заказе больше одного раза. Измени готовую функцию, не пиши её с нуля.

## Аргументы

- `order` — словарь `{"items": [{"name": ..., "qty": ...}, ...], "budget": ...}`; цены в словаре `PRICES` в файле задачи.

## Возвращает

`"ok"` или код первой сработавшей проверки в порядке: `"no_items"`, `"duplicate_item"`, `"bad_qty"`, `"unknown_item"`, `"over_budget"`.

## Правила

- Измени готовый код: добавь новую проверку на нужное место, остальные не трогай.
- Заказ не меняй.
- `try`/`except` не используй.
- Функция должна **вернуть** значение через `return`, а не печатать его.

## Пример

```python
task_er09_validate_order({"items": [{"name": "чай", "qty": 1}, {"name": "чай", "qty": 2}], "budget": 500})
# -> "duplicate_item"
task_er09_validate_order({"items": [{"name": "чай", "qty": 2}], "budget": 300})
# -> "ok" (как раньше)
```

## Учебные цели

- Вставлять новую проверку в цепочку на правильное место.
- Не ломать старое поведение при правке.

## Проверка понимания

Что вернёт заказ `чай x0, чай x1` до правки и что после? Почему порядок кодов — часть договора?
