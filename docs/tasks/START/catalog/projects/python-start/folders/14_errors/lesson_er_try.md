# try/except/else/finally: поймать конкретную ошибку

Исключение можно **поймать** и продолжить работу. Для этого опасный код кладут в `try`, а в `except ТипОшибки` пишут, что делать при такой ошибке.

```python
def safe_int(text, default):
    try:
        return int(text)
    except ValueError:
        return default
```

`safe_int("42", 0)` вернёт `42`, а `safe_int("abc", 0)` — `0`: `int("abc")` бросит `ValueError`, Python пропустит остаток `try` и перейдёт в `except`.

## Четыре части

```python
log = ""                    # 1
try:                        # 2
    log = log + "a"         # 3
    n = int("7")            # 4
except ValueError:          # 5
    log = log + "b"         # 6
else:                       # 7
    log = log + "c"         # 8
finally:                    # 9
    log = log + "d"         # 10
```

| Часть | Когда выполняется |
|---|---|
| `try` | всегда, но обрывается на первой ошибке |
| `except` | только если в `try` была подходящая ошибка |
| `else` | только если в `try` ошибки **не было** |
| `finally` | **всегда**, в конце |

Здесь ошибки нет, поэтому `log` станет `"acd"`. Для `int("x")` было бы `"abd"`: строка 3 выполнится, строка 4 бросит ошибку, строки 5–6 и 9–10 сработают, а `else` пропустится.

## Ловим конкретный тип

`except ValueError` ловит только `ValueError`. Остальные ошибки пролетят мимо и будут видны. Это правильно: ты ждёшь неверный текст, а не любую поломку.

Сообщение ошибки берут так: `except ValueError as error:` и дальше `str(error)`.

**Голый `except:` ловит всё, и это опасно.** Он прячет баги:

```python
def to_cents(text):
    try:
        rubles = int(text)
        return rubls * 100       # опечатка: NameError
    except:                      # голый except молча проглотит NameError
        return -1
```

Любой текст даст `-1`, и ошибки в коде не видно. С `except ValueError:` опечатка сразу бы сообщила о себе.

## Как задачи проверяют исключения

Тесты сравнивают только **возвращаемые значения**, поэтому в задачах, где нужно показать исключение, его ловит помощник `given_capture(fn, *args)`. Он вызывает `fn(*args)` и либо возвращает результат, либо `["error", "ТипОшибки", "сообщение"]`:

```python
given_capture(int, "7")      # -> 7
given_capture(int, "x")      # -> ["error", "ValueError", "invalid literal for int() with base 10: 'x'"]
```

Помощник уже написан в начале файла задачи; имя начинается с `given_`, его не нужно менять.

## Частые ошибки

Поставить в `try` слишком много кода: ошибка из другой строки молча уйдёт в тот же `except`. В `try` оставляют только то, что может бросить ожидаемую ошибку.

`finally` с `return` внутри перебивает всё: ответ из `try` потеряется. Возвращай значения не из `finally`.

## Проверь себя

```python
def f(text):
    try:
        n = int(text)
    except ValueError:
        return "плохо"
    else:
        return n * 2
    finally:
        print("готово")
```

1. Что вернёт `f("4")` и что `f("a")`?
2. Сколько раз напечатается «готово» в каждом случае?

<details><summary>Ответ</summary>

1. `f("4")` вернёт `8` (сработал `else`), `f("a")` вернёт `"плохо"`.
2. Один раз в каждом: `finally` выполняется всегда, даже когда внутри уже был `return`.

</details>
