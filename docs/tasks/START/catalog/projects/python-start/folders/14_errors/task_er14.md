# Задача ER14: Отказ выглядит как успех

## Условие

### Как это работает

Функция-обёртка получает от готового обработчика словарь `{"ok", "state", "value", "error"}` и должна превратить его в ответ единого формата:

| Обработчик вернул | Ответ обёртки |
|---|---|
| `ok = True` | `{"status": "done", "state": новое, "result": value, "reason": None}` |
| `ok = False` | `{"status": "rejected", "state": исходное, "result": None, "reason": error}` |

Багом называют ситуацию, когда ответ при отказе выглядит как успех:

```python
answer = {"status": "done", "state": handled["state"], "result": handled["value"], "reason": None}
if not handled["ok"]:
    answer["reason"] = handled["error"]      # причина записана, но status остался "done"
return answer
```

Для `ok = False` получится `{"status": "done", "state": ..., "result": None, "reason": "not_enough"}`. Тот, кто смотрит только на `status`, решит, что действие выполнено, хотя оно отклонено. Такой «ложный успех» опаснее обычной ошибки: никто не заметит.

Чинят это целиком: **на каждую ветку свой полный ответ**, а не один ответ с исправлениями.

### Задание

Состояние склада — словарь `{"stock": {название: количество}}`. Готовый `given_apply(state, command)` применяет команду и возвращает `{"ok", "state", "value", "error"}`; порядок проверок в нём: `unknown_tool`, `bad_qty`, затем (для `take`) `unknown_item`, `not_enough`. Функция `task_er14_run` должна превратить его ответ в единый формат, но сейчас при отказе пишет `"done"`. Найди ошибку и исправь.

### Что дальше

Это тот же баг, что в продуктовой задаче [XL-A14](task:XL-A14), только там вместо склада события гильдии. Теперь ты знаешь, как его искать: проверь `status` в ветке отказа.

## Аргументы

- `state` — словарь `{"stock": {...}}`.
- `command` — словарь `{"tool": "put" или "take", "item": название, "qty": число}`.

## Возвращает

Словарь `{"status", "state", "result", "reason"}`. При успехе `status` равен `"done"`, `state` и `result` берутся из обработчика, `reason` равен `None`. При отказе `status` равен `"rejected"`, `state` остаётся исходным, `result` равен `None`, `reason` — код обработчика.

## Правила

- Исправь только `task_er14_run`; `given_apply` не меняй.
- Входные данные не меняй.
- Функция должна **вернуть** значение через `return`, а не печатать его.

## Пример

```python
state = {"stock": {"яблоки": 3}}
task_er14_run(state, {"tool": "take", "item": "яблоки", "qty": 5})
# -> {"status": "rejected", "state": {"stock": {"яблоки": 3}}, "result": None, "reason": "not_enough"}
task_er14_run(state, {"tool": "take", "item": "яблоки", "qty": 2})
# -> {"status": "done", "state": {"stock": {"яблоки": 1}}, "result": {"item": "яблоки", "qty": 2}, "reason": None}
```

## Учебные цели

- Находить «ложный успех»: статус, не соответствующий результату.
- Строить на каждую ветку свой полный ответ.

## Проверка понимания
