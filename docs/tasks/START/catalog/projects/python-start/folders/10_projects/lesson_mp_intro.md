# Мини-проекты: как работать над проектом по шагам

До сих пор каждая задача была отдельной. Здесь по-другому: в папке четыре **мини-проекта**, и в каждом по пять шагов. Каждый шаг строится на предыдущем и добавляет **одно** новое требование. К концу проекта у тебя получится маленькая работающая программа.

| Проект | Шаги | Что получится |
|---|---|---|
| «Угадай число» | MP01–MP05 | подсказки, подсчёт попыток, отчёт об игре, лимит, лучшая стратегия |
| «Шифр Цезаря» | MP06–MP10 | сдвиг буквы, шифрование, расшифровка, русский алфавит, взлом |
| «Надёжный пароль» | MP11–MP15 | проверка длины, список проблем, оценка, новые правила, совет |
| «Системы счисления» | MP16–MP20 | двоичная запись, любое основание, обратный перевод, минус, конвертер |

## Как устроен шаг

В файле шага сверху лежит блок `готово с прошлого шага`. Это **рабочие функции**, которые ты написал (или мог написать) раньше. Их можно вызывать, но менять не нужно. Ниже находится твоя функция.

```python
# ===== готово с прошлого шага: вызывай, но не меняй =====
def check_guess(secret, guess):
    ...
# ===== конец готового кода =====

def task_mp02_count_tries(secret, guesses):
    return None  # твой код
```

Шаги бывают двух видов:

| Вид | Что делаешь |
|---|---|
| `write` | пишешь новую функцию, вызывая готовые |
| `modify` | в файле лежит **старая версия** твоей функции; её нужно изменить под новое правило |

## Правило проекта: после каждого изменения запускай старые примеры

Изменение легко **сломать то, что уже работало**. Поэтому порядок такой:

1. Прочитай, что именно меняется. Требование всегда одно.
2. Запусти примеры из условия (старые и новые) и посмотри, какие ответы уже верные.
3. Внеси изменение **небольшим кусочком**.
4. Снова запусти те же примеры: старые должны остаться верными, новые должны начать работать.

## Пример: изменение, которое ломает старое

Было: функция `double(x)` возвращает `x * 2`. Новое требование: для отрицательных чисел вернуть `0`.

| Версия | `double(4)` | `double(-4)` |
|---|---|---|
| исходная | `8` | `-8` |
| вместо `x * 2` написали `0` | `0` (сломали!) | `0` |
| добавили `if x < 0: return 0` | `8` | `0` |

Третий вариант добавляет новое правило и сохраняет прежнее поведение.

## Частые ошибки

Переписать функцию с нуля, когда просили изменить: появляется много новых ошибок.

```python
def double(x):
    return 0                # неверно: старое поведение потеряно
```

```python
def double(x):
    if x < 0:
        return 0            # верно: добавили правило, остальное как было
    return x * 2
```

## Проверь себя

В проекте тебе дали функцию `f(x)` с примерами `f(3) -> 6` и `f(0) -> 0`, а новое правило касается только `x < 0`.

1. Какие примеры ты запустишь после изменения?
2. Почему нельзя проверять только новое правило?

<details><summary>Ответ</summary>

1. Все: `f(3)`, `f(0)` и новые случаи с отрицательными числами.
2. Новое правило могло сломать прежний случай; это видно только если запустить старые примеры тоже.

</details>
