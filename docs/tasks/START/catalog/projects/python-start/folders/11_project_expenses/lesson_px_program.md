# Программа как состояние и команды: функция handle

Настоящая программа работает с **памятью**: пользователь вводит одно действие за другим, и каждое действие видит то, что было до него. В учёте расходов память — это **список расходов**, а действие — **строка команды**: `add 120 кафе`.

## Три части программы

| Часть | Что это в нашем проекте |
|---|---|
| состояние | `entries` — список пар `[сумма, категория]`: `[[120, "кафе"], [50, "еда"]]` |
| команда | строка: что сделать и с какими значениями |
| ответ | строка, которую программа печатает: `"Записал: 120 ₽ — кафе"` |

Главная функция программы — `handle(entries, line)`. Она берёт состояние и одну строку, может **изменить состояние** (`entries.append(...)`, `entries.pop()`) и **возвращает** ответ.

```python
def handle(entries, line):
    words = line.strip().split()              # ["add", "120", "кафе"]
    command = words[0].lower()                # "add"
    if command == "add":
        entries.append([int(words[1]), words[2]])   # состояние изменилось
        return f"Записал: {words[1]} ₽ — {words[2]}"
    return "Не понимаю команду. Напиши help."
```

В задачах проекта разбор строки вынесен в отдельную функцию `parse_command` (урок `px-parsing`): `handle` получает уже готовые `command` и `args` и проверяет аргументы **до** записи. Смысл тот же: `handle` меняет `entries` и возвращает строку-ответ.

## Почему состояние живёт в списке

Список передаётся в функцию **по ссылке**: `entries` внутри `handle` — это тот же самый список, что снаружи. Значит, `append` и `pop` меняют его для всех. Функция ничего не возвращает «обратно» — она меняет общий список и отвечает строкой.

## Цикл программы: main

Настоящая программа читает команды до слова `exit`. Этот цикл уже **готов** в каждом шаге проекта:

```python
def main():
    entries = []
    while True:
        line = input("> ")
        if line == "exit":
            break
        print(handle(entries, line))


if __file__ == sys.argv[0]:
    main()
```

Последняя строка — **защита**: `main()` запускается только тогда, когда файл запустили как программу. Проверялка приписывает к твоему файлу свой код и импортирует его — в этом случае условие ложно, и `main()` не запускается.

`input()` останавливает программу и ждёт строку. Если файл запустить как программу, но не вводить команды, он будет ждать вечно — виноват не твой `handle`, а `main`.

## Почему проверяют сценарии

Одна команда сама по себе мало что показывает. Ошибки программы видны, когда команды идут **подряд**:

| Строка | Что осталось в `entries` | Ответ |
|---|---|---|
| `add 120 кафе` | `[[120, "кафе"]]` | `Записал: 120 ₽ — кафе` |
| `add 50 еда` | `[[120, "кафе"], [50, "еда"]]` | `Записал: 50 ₽ — еда` |
| `total` | без изменений | `Всего: 170 ₽` |

Поэтому в проверке каждой задачи несколько команд идёт подряд и сверяются **все** ответы. Если `add` не записал расход, правильный ответ на `total` не появится.

## Пример целиком: трассировка сценария

`task_px01_session(["add 120 кафе", "add 50 еда", "total"])` прогоняет строки по порядку и собирает ответы в список:

| № | Строка | `entries` до вызова | `entries` после вызова | Ответ в списке |
|---|---|---|---|---|
| 1 | `add 120 кафе` | `[]` | `[[120, "кафе"]]` | `Записал: 120 ₽ — кафе` |
| 2 | `add 50 еда` | `[[120, "кафе"]]` | `[[120, "кафе"], [50, "еда"]]` | `Записал: 50 ₽ — еда` |
| 3 | `total` | `[[120, "кафе"], [50, "еда"]]` | без изменений | `Всего: 170 ₽` |

Итог функции: `['Записал: 120 ₽ — кафе', 'Записал: 50 ₽ — еда', 'Всего: 170 ₽']`. Каждый ответ зависит от **всей** истории: `total` на шаге 3 знает про оба расхода только потому, что `entries` — один и тот же список, а `handle` менял его на месте.

## Как шаг меняет программу, не ломая старое

1. Готовый код прошлого шага лежит в блоке «готово с прошлого шага».
2. Добавь **одну** ветку для новой команды (или поправь одну ветку, если меняется поведение).
3. Прогони примеры прошлых шагов: они должны отвечать **как раньше**.
4. Прогони новые примеры.

То же правило, что в папке 09 (карточка `fd-modify`), но теперь меняется целая программа.

## Частые ошибки

Возвращать изменённый список вместо ответа:

```python
def handle(entries, line):
    entries.append([100, "кафе"])
    return entries               # неверно: программа напечатает список, а не текст
```

```python
def handle(entries, line):
    entries.append([100, "кафе"])
    return "Записал: 100 ₽ — кафе"   # верно: ответ — строка
```

Сделать копию состояния и забыть, что изменения не сохранятся:

```python
def handle(entries, line):
    entries = entries + [[100, "кафе"]]   # неверно: это новый список, внешний не изменился
```

## Проверь себя

```python
entries = []
handle(entries, "add 100 кафе")
handle(entries, "add 50 еда")
```

1. Чему равен `entries` после двух вызовов?
2. Почему работают оба вызова, хотя `handle` не возвращает список?

<details><summary>Ответ</summary>

1. `[[100, "кафе"], [50, "еда"]]`.
2. `entries` — один и тот же список снаружи и внутри функции; `append` меняет его на месте, поэтому изменения видны всем.

</details>
