# Задача PX07: Лимит на категорию

## Условие

### Как это работает

Программа научилась считать деньги, но не умеет остановить себя: лимит на категорию — самый полезный для бюджета датчик. Это **вторая память** программы, параллельная `entries`.

**Новый список `limits`.** Это список пар `[категория, лимит]`, например `[["кафе", 100], ["такси", 300]]`. Рядом с `entries` его ведёт та же функция-обработчик, поэтому у `handle` появляется **второй список** в аргументах:

```python
def handle(entries, limits, line):
```

Такой же список нужен и `main`: иначе цикл программы не сможет работать. Сценарий тоже создаёт оба списка:

```python
def task_px07_session(lines):
    entries = []
    limits = []
    ...
```

`entries` и `limits` — два независимых живых списка: `add` меняет только `entries`, `limit` — только `limits`. Порядок в `limits` не важен: категорию ищут перебором.

**`limit <категория> <сумма>`.** Сумма лимита проверяется так же, как сумма расхода: `isdigit()` и `> 0`. Если категория уже есть в `limits`, её лимит **заменяется**: `limit[1] = int(amount)` — без второго такого же элемента в списке. Иначе пара добавляется через `append`.

```python
for limit in limits:
    if limit[0] == args[0]:
        limit[1] = int(amount)   # меняем у существующей пары
        return f"Лимит на {args[0]}: {amount} ₽"
limits.append([args[0], int(amount)])
return f"Лимит на {args[0]}: {amount} ₽"
```

**Предупреждение.** После записи расхода пересчитываем, сколько потрачено **на эту категорию**, и ищем её лимит:

```python
spent = 0
for entry in entries:
    if entry[1] == args[1]:
        spent = spent + entry[0]
for limit in limits:
    if limit[0] == args[1] and spent > limit[1]:
        over = spent - limit[1]
        return reply + f"\nВнимание: лимит на {args[1]} превышен на {over} ₽"
```

Ответ `Записал: …` сохраняется, предупреждение идёт **второй строкой** — одним ответом с `\n` внутри, а не отдельным вызовом. Условие строгое: ровно лимит (`spent == limit[1]`) — это ещё не превышение. Предупреждение появляется в тот момент, когда сумма перешла черту, и не повторяется на следующих расходах, если лимит не превышен снова.

**Что меняется по сравнению с прошлым шагом (PX06):** у `handle` и `main` появляется аргумент `limits`, у `task_px07_session` — список `limits`; `add` дополнительно проверяет лимит; появляется команда `limit`. Сценарии прошлых шагов должны отвечать как раньше: если лимитов нет, `add`, `total`, `report`, `undo` и `help` работают по-прежнему.

### Задание

Добавь список `limits`, команду `limit` и вторую строку предупреждения в ответе `add`. Остальное не меняй.

## Аргументы

- `entries` — список расходов `[сумма, категория]` (изменяется на месте).
- `limits` — список лимитов `[категория, лимит]` (изменяется на месте).
- `lines` — список строк-команд сценария (может быть пустым).

## Возвращает

`task_px07_session` — список ответов. Для `limit` — `Лимит на <категория>: <сумма> ₽`; при неверной сумме — `Сумма должна быть целым числом больше нуля`; если указан только один аргумент или ни одного — `Укажи категорию и сумму лимита`. Для `add` с превышением — `Записал: … ₽ — …` и второй строкой `Внимание: лимит на <категория> превышен на <сумма> ₽` в одной строке ответа через `\n`.

## Правила

- Меняй `handle` и `main` (новый аргумент `limits`); остальные команды оставь как были.
- Функция должна **вернуть** строку через `return`, а не печатать её.
- Встроенные `sum`, `sorted`, `max` не используй: суммы считай циклами.
- Повторный `limit` на ту же категорию заменяет старый лимит, а не добавляет второй.

## Пример

```python
task_px07_session(["limit кафе 100", "add 80 кафе", "add 50 кафе"])
# -> ['Лимит на кафе: 100 ₽', 'Записал: 80 ₽ — кафе',
#     'Записал: 50 ₽ — кафе\nВнимание: лимит на кафе превышен на 30 ₽']
task_px07_session(["limit кафе 100", "add 100 кафе"])
# -> ['Лимит на кафе: 100 ₽', 'Записал: 100 ₽ — кафе']
```

## Учебные цели

- Вести вторую «память» программы отдельным списком-аргументом.
- Сравнивать накопленную сумму с лимитом и добавлять предупреждение второй строкой.
