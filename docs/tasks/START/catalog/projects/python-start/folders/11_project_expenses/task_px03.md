# Задача PX03: Проверка суммы и категории

## Условие

### Как это работает

Сейчас `add` верит пользователю на слово: `int(args[0])` упадёт на `add abc кафе`, а `add 0 кафе` запишет нулевой расход. Нужно **проверить** аргументы до записи (урок `px-parsing`).

Сумма приходит из `split()` строкой. `isdigit()` отвечает, состоит ли строка только из цифр, и только потом можно делать `int(...)`. Нужны **две** проверки:

| Строка | `isdigit()` | сумма больше нуля? | ответ |
|---|---|---|---|
| `"120"` | `True` | да | записываем |
| `"0"` | `True` | нет | «Сумма должна быть целым числом больше нуля» |
| `"-50"` | `False` | — | «Сумма должна быть целым числом больше нуля» |
| `"12.5"` | `False` | — | «Сумма должна быть целым числом больше нуля» |
| `"abc"` | `False` | — | «Сумма должна быть целым числом больше нуля» |

Проверки нужны **до** обращения к аргументам, которых может не быть: `add` без суммы и `add 120` без категории. Порядок такой:

```python
if len(args) < 1:                          # 1: суммы нет
    return "Сумма должна быть целым числом больше нуля"
if not args[0].isdigit() or int(args[0]) == 0:   # 2: не число или ноль
    return "Сумма должна быть целым числом больше нуля"
if len(args) < 2:                          # 3: суммы уже хорошая, а категории нет
    return "Укажи категорию"
entries.append([int(args[0]), args[1]])    # 4: теперь можно записывать
return f"Записал: {args[0]} ₽ — {args[1]}"
```

Если переставить шаги 2 и 3, `add 0` ответит «Укажи категорию», а проверка ждёт ответ про сумму. Если сделать `int(args[0])` раньше `isdigit()`, программа упадёт на тексте.

**Что меняется по сравнению с прошлым шагом (PX02):** внутри ветки `add` перед записью появляются три проверки. Строки записи и ответ `Записал: …` остаются прежними; `total`, `help` и ответ «Не понимаю команду.» не меняются.

Сценарии прошлых шагов должны отвечать как раньше: `add 120 кафе` → `Записал: 120 ₽ — кафе`, `total` → `Всего: …`, `help` → справка.

### Задание

Измени `handle` так, чтобы `add` сначала проверял сумму и категорию, а записывал расход только после успешных проверок. Остальное оставь как есть.

## Аргументы

- `lines` — список строк-команд сценария (может быть пустым).

## Возвращает

`task_px03_session` — список ответов. Для `add` с правильными аргументами — `Записал: <сумма> ₽ — <категория>`; если суммы нет, она не число или равна `0` — `Сумма должна быть целым числом больше нуля`; если суммы нет вообще — тоже этот ответ; если сумма правильная, а категории нет — `Укажи категорию`.

## Правила

- Меняй только `handle`; готовый код остальных команд и цикл не трогай.
- Функция должна **вернуть** строку через `return`, а не печатать её.
- Проверяй строку через `isdigit()` **до** `int(...)`; `try`/`except` не используй.
- Ошибочная команда не должна записывать расход: `total` после ошибок не меняется.

## Пример

```python
task_px03_session(["add 0 кафе"])          # -> ['Сумма должна быть целым числом больше нуля']
task_px03_session(["add abc кафе"])        # -> ['Сумма должна быть целым числом больше нуля']
task_px03_session(["add 120"])             # -> ['Укажи категорию']
task_px03_session(["add 120 кафе", "add 0 кафе", "total"])
# -> ['Записал: 120 ₽ — кафе', 'Сумма должна быть целым числом больше нуля', 'Всего: 120 ₽']
```

## Учебные цели

- Проверять текст-число через `isdigit()` до преобразования.
- Расставлять проверки в таком порядке, чтобы не было ошибки из-за отсутствующего аргумента.
