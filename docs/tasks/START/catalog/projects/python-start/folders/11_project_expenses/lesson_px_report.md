# Отчёт: f-строки, порядок категорий и проценты

Команда `report` печатает несколько строк: сколько потрачено на каждую категорию и сколько всего. Шаблон такой: `"кафе: 150 ₽"`. Строку собирают **f-строкой**.

## Сборка строк

```python
line = f"{category}: {amount} ₽"      # "кафе: 150 ₽"
```

Несколько строк склеивают через `join` с разделителем перевода строки `"\n"`:

```python
text = "\n".join(lines)               # "кафе: 150 ₽\nеда: 80 ₽"
```

`"\n"` — это один символ «новая строка». Когда его напечатают, каждая часть встанет на свою строку.

## Порядок категорий

Порядок в отчёте **не случайный**. На шаге `report` категории идут в порядке **первого появления** в списке расходов.

| Расходы | Порядок | Отчёт |
|---|---|---|
| `[[80, "еда"], [150, "кафе"]]` | еда, кафе | еда: 80 ₽, потом кафе: 150 ₽ |
| `[[150, "кафе"], [80, "еда"]]` | кафе, еда | кафе: 150 ₽, потом еда: 80 ₽ |

Его получают так: идут по расходам слева направо и добавляют в список сборщик только категорию, которую ещё не видели:

```python
seen = []
for entry in entries:
    if entry[1] not in seen:
        seen.append(entry[1])
```

`in` проверяет, есть ли уже категория в `seen`. Теперь цикл по `seen` даст строки в нужном порядке.

## Сортировка по сумме

На шаге PX06 порядок другой: **сначала самые дорогие**. Чтобы отсортировать пары «категория — сумма» и не потерять, какая сумма к какой категории относится, в курсе используют **два списка одинаковой длины**: `order` и `sums`, где `sums[i]` — сумма категории `order[i]`. Их сортируют **своими циклами обмена**, переставляя обе пары одновременно:

```python
for i in range(len(sums)):
    for j in range(i + 1, len(sums)):
        if sums[j] > sums[i]:
            sums[i], sums[j] = sums[j], sums[i]     # суммы местами
            order[i], order[j] = order[j], order[i] # и категории тоже
```

`sums[i], sums[j] = sums[j], sums[i]` — обмен двух переменных в одной строке. Условие `sums[j] > sums[i]` строгое: при **равных** суммах пары не меняются, поэтому категории с одинаковой суммой остаются в порядке первого появления.

## Проценты: round

Долю категории считают так: `amount * 100 / total`. Это дробное число. `round(...)` округляет до целого:

```python
share = round(amount * 100 / total)   # 150 из 230 → round(65.217...) → 65
f"{category}: {amount} ₽ ({share}%)"  # "кафе: 150 ₽ (65%)"
```

Ответ `round` — число (`65`), а не строка: `65` печатается без `str(...)` только внутри f-строки.

## Пример целиком: трассировка отчёта

`entries = [[150, "такси"], [100, "кафе"], [60, "еда"]]`, `total = 310`.

**Шаг 1 — сбор `order` и `sums`** (категория ещё не встречалась → добавляем пару с нулём, затем прибавляем сумму):

| Расход | `order` после | `sums` после |
|---|---|---|
| `[150, "такси"]` | `["такси"]` | `[150]` |
| `[100, "кафе"]` | `["такси", "кафе"]` | `[150, 100]` |
| `[60, "еда"]` | `["такси", "кафе", "еда"]` | `[150, 100, 60]` |

**Шаг 2 — сортировка обменом:** `i = 0` сравнивает `100 > 150` (нет), `60 > 150` (нет); `i = 1` сравнивает `60 > 100` (нет). Порядок уже правильный: `["такси", "кафе", "еда"]`, `[150, 100, 60]`.

**Шаг 3 — строки:**

| Категория | Сумма | `round(сумма * 100 / 310)` | Строка |
|---|---|---|---|
| такси | 150 | `round(48.38...)` → 48 | `такси: 150 ₽ (48%)` |
| кафе | 100 | `round(32.25...)` → 32 | `кафе: 100 ₽ (32%)` |
| еда | 60 | `round(19.35...)` → 19 | `еда: 60 ₽ (19%)` |

Итог: `"такси: 150 ₽ (48%)\nкафе: 100 ₽ (32%)\nеда: 60 ₽ (19%)\nИтого: 310 ₽"`.

## Частые ошибки

Забыть `"\n".join` и вернуть список — программа напечатает его с квадратными скобками и кавычками:

```python
return lines                       # неверно: ['кафе: 150 ₽', 'еда: 80 ₽']
return "\n".join(lines)            # верно: две строки
```

Считать процент от числа расходов вместо суммы, делить на ноль, когда расходов нет. Пока в отчёте есть хотя бы одна строка, `total` больше нуля — это стоит проверить условием «расходов нет».

`round(2.5)` даёт `2` (округление к чётному, карточка `n-rounding-math`). Поэтому проценты подбирают так, чтобы ровно половин не было.

Поменять суммы местами, а категории забыть: тогда `order[i]` перестанет соответствовать `sums[i]`, и отчёт покажет сумму одной категории под именем другой.

## Проверь себя

```python
entries = [[100, "кафе"], [100, "еда"], [50, "кафе"]]
```

1. Какие категории и в каком порядке появятся?
2. Чему равны итоги и `total`?

<details><summary>Ответ</summary>

1. Порядок первого появления — кафе, еда. Сортировка по сумме при равных `150` и `150` этот порядок сохранит.
2. кафе: `150`, еда: `100`, `total` = `350`.

</details>
