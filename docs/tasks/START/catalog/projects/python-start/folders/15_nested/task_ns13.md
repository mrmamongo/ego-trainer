# Задача NS13: delete_path сообщает, что удалено

## Условие

### Как это работает

Когда удаление делает несколько действий сразу (убрало значение, а потом опустевшие ветки), вызывающему полезно знать, что именно исчезло. Раньше `delete_path` возвращала только новую структуру. Теперь она возвращает два результата сразу, словарём `{"data": ..., "removed": [...]}`.

`removed` это список путей, склеенных точками, **в порядке удаления**: сначала само значение, потом каждая опустевшая ветка снизу вверх.

| Данные | Путь | `data` | `removed` |
|---|---|---|---|
| `{"a": {"b": 1, "c": 2}}` | `["a", "b"]` | `{"a": {"c": 2}}` | `["a.b"]` |
| `{"a": {"b": 1}}` | `["a", "b"]` | `{}` | `["a.b", "a"]` |
| `{"a": {"b": {"c": 1}}}` | `["a", "b", "c"]` | `{}` | `["a.b.c", "a.b", "a"]` |
| `{"a": {"b": 1}}` | `["a", "x"]` | то же | `[]` |

Удалили целую ветку одним ключом, например `["a"]` при `{"a": {"b": 1, "c": 2}}`: в `removed` один путь `["a"]`, внутренности по отдельности не перечисляются.

Рекурсивный вызов теперь тоже возвращает словарь. Пути из внутреннего `removed` нужно начать с ключа текущего уровня: `key + "." + name`. Если ветка опустела, её путь (`key`) добавляется **после** внутренних.

### Задание

Раньше функция `task_ns13_delete_path(data, path)` возвращала новую структуру, теперь она возвращает `{"data": новая_структура, "removed": список_путей}`. Правила удаления и очистки пустых веток остались прежними. Измени готовую функцию, не пиши её с нуля.

## Аргументы

- `data` — словарь с ключами-строками; значения: словари и простые значения.
- `path` — непустой список ключей-строк.

## Возвращает

Словарь `{"data": ..., "removed": [...]}`. Если пути нет, `data` равна входной структуре, а `removed` пуст.

## Правила

- Измени готовый код; `given_deep_copy` оставь.
- Входной `data` не меняй, в том числе вложенные словари.
- В результате не должно быть общих со входом словарей и списков.
- Модуль `copy` не используй.
- Функция должна **вернуть** значение через `return`, а не печатать его.

## Пример

```python
task_ns13_delete_path({"a": {"b": 1}, "c": 2}, ["a", "b"])
# -> {"data": {"c": 2}, "removed": ["a.b", "a"]}
```

## Учебные цели

- Расширить результат рекурсивной функции, не сломав старую логику.
- Склеивать пути из результатов вложенных вызовов.

## Проверка понимания

Почему в `removed` сначала идёт `"a.b"`, а потом `"a"`? Что будет в `removed`, если удалить `["a", "x"]`, а `"a"` был пустым словарём с самого начала?
