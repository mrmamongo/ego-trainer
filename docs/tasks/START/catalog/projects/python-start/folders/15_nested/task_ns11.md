# Задача NS11: set_path с отказом: на пути не словарь

## Условие

### Как это работает

Старая `set_path` из `NS08` молча заменяла любое значение на пути новым словарём. Если у пользователя было `{"role": "tank"}`, а мы записываем `["role", "name"]`, строка `"tank"` пропадала без следа. Это потеря данных, и пользователь об этом не узнаёт.

Поэтому правило меняется: **путь через не словарь это отказ**. Отказ это не исключение, а значение в формате из карточки `er-codes`: словарь с `status`, `data`, `reason` и новым полем `at`, местом, где путь упёрся.

| Случай | `status` | `data` | `reason` | `at` |
|---|---|---|---|---|
| записали | `"done"` | новая структура | `None` | `None` |
| на пути не словарь | `"rejected"` | **исходные** данные (копия) | `"not_a_dict"` | путь до этого значения, ключи через точку |

`at` показывает путь к значению, которое не оказалось словарём, а не к тому, что хотели записать. Для данных `{"a": {"b": 5}}` и пути `["a", "b", "c"]` значение `5` лежит по `a.b`, поэтому `at` равен `"a.b"`.

Что остаётся как раньше: недостающие ветки создаются; **последний** ключ можно записать поверх чего угодно (число, словарь), отказ даёт только промежуточное не-словарь значение. Отказ не должен частично менять результат: сначала проверяем путь, потом пишем.

### Задание

Раньше функция `task_ns11_set_path(data, path, value)` возвращала просто новую структуру. Теперь она возвращает словарь `{"status", "data", "reason", "at"}` по таблице выше. Измени готовую функцию, не пиши её с нуля.

## Аргументы

- `data` — словарь с ключами-строками; значения: словари, списки, простые значения.
- `path` — непустой список ключей-строк.
- `value` — простое значение.

## Возвращает

Словарь `{"status", "data", "reason", "at"}`: при успехе `done` и новая структура, при отказе `rejected`, исходные данные, `"not_a_dict"` и путь `at`.

## Правила

- Измени готовый код, а не переписывай с нуля; `given_deep_copy` оставь.
- Входной `data` не меняй, в том числе вложенные словари.
- В результате (в том числе в поле `data` при отказе) не должно быть общих со входом словарей и списков.
- Модуль `copy` не используй.
- Функция должна **вернуть** значение через `return`, а не печатать его.

## Пример

```python
task_ns11_set_path({"a": {"b": 1}}, ["a", "b"], 2)
# -> {"status": "done", "data": {"a": {"b": 2}}, "reason": None, "at": None}

task_ns11_set_path({"role": "tank"}, ["role", "name"], "Mira")
# -> {"status": "rejected", "data": {"role": "tank"}, "reason": "not_a_dict", "at": "role"}
```

## Учебные цели

- Заменить молчаливую порчу данных на явный отказ.
- Строить значение-отказ в формате `{status, reason}`.

## Проверка понимания

Почему `at` для `["a", "b", "c"]` равен `"a.b"`, а не `"a.b.c"`? Что вернётся при записи `["a", "b"]` в `{"a": 5}`: отказ или успех?
