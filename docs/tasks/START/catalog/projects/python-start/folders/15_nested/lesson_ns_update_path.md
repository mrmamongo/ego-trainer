# Записать и удалить по пути: новая структура

Функции `set_path` и `delete_path` **не меняют вход**: они возвращают новую структуру. Из карточки про копии ты знаешь: `dict(a)` копирует один уровень, а вложенное остаётся общим. Здесь это главный вопрос: **сколько копировать?**

## Вариант 1: копируем только ветку, которую меняем

Копия делается на каждом уровне пути, а всё остальное остаётся тем же самым объектом:

```python
def set_path_shared(data, path, value):
    result = dict(data)                      # копия этого уровня
    key = path[0]
    if len(path) == 1:
        result[key] = value
    else:
        child = data.get(key)
        if type(child) is not dict:
            child = {}
        result[key] = set_path_shared(child, path[1:], value)
    return result
```

Это быстро и экономно: соседние ветки не копируются. Но у результата и входа остаются **общие** ветки: `result["other"] is data["other"]`. Пока никто их не меняет, всё хорошо. Как только кто-то изменит такую ветку в результате, она изменится и во входе.

## Вариант 2: копируем всё

```python
def set_path(data, path, value):
    result = given_deep_copy(data)           # ничего общего со входом
    current = result
    for key in path[:-1]:
        if key not in current or type(current[key]) is not dict:
            current[key] = {}                # создаём недостающую ветку
        current = current[key]
    current[path[-1]] = value                # правим уже копию
    return result
```

Сначала полная копия, потом правки **в копии**. Так проще и надёжнее.

## Какой вариант нужен в задачах

Во всех задачах папки нужен **вариант 2**: у результата и входа не должно быть ни одной общей коробки. Проверка это ловит (`result shares mutable data with input`). Причина из продукта: два пользователя могут ссылаться на один и тот же внутренний словарь, и правка у одного «протекает» к другому. Полная копия такую утечку исключает.

Полную копию в задачах `NS08`, `NS09`, `NS11`, `NS13`, `NS14` даёт готовый помощник `given_deep_copy`. Как она устроена, ты напишешь сам в следующей карточке и в задаче `NS10`.

## Удаление по пути и очистка пустых веток

Удалить ключ: `del result[key]` в копии. Если после этого словарь опустел, он больше ничего не хранит, и его тоже убирают из родителя:

| Данные | Путь | Результат |
|---|---|---|
| `{"a": {"b": 1, "c": 2}}` | `["a", "b"]` | `{"a": {"c": 2}}` |
| `{"a": {"b": 1}}` | `["a", "b"]` | `{}` (`"a"` опустел, его убрали) |
| `{"a": {"b": 1}}` | `["a", "x"]` | `{"a": {"b": 1}}` (такого пути нет, ничего не меняется) |

Убирают только словарь, который опустел **из-за удаления**. Словарь, который был пустым с самого начала, не трогают.

## Частые ошибки

```python
def set_path(data, path, value):
    data[path[0]] = value          # неверно: правим вход
    return data
```

```python
result = dict(data)
result["a"]["b"] = 1               # неверно: "a" общий со входом, поправили оригинал
```

## Проверь себя

```python
data = {"a": {"b": 1}, "c": {"d": 2}}
result = set_path_shared(data, ["a", "b"], 5)
```

1. Что общего у `data["c"]` и `result["c"]`?
2. Изменится ли `data["a"]`?

<details><summary>Ответ</summary>

1. Это один и тот же словарь: ветку `"c"` не меняли, и она не копировалась.
2. Нет: ветка `"a"` была скопирована, правка пошла в копию. Но общая ветка `"c"` остаётся ловушкой.

</details>
