# Бриф: переработка страницы студента

Документ для агента, который будет переделывать кабинет студента в браузере. Всё ниже
проверено по ветке `claude/thematic-task-sets-bdd914` и продакшену на 2026-10-24.
Парный документ — [LANDING_BRIEF.md](LANDING_BRIEF.md) (там подробно про сервер, шлюз и выкатку;
здесь повторено только нужное).

**Работай в своём git worktree**, не в чужом. В прошлый раз агент лендинга писал в рабочую
копию другой сессии.

## 1. Зачем

Основная работа студента теперь в VS Code: расширение показывает задачи, теорию, проверку,
интерактивные тренажёры и личный кабинет. Веб-кабинет `/student` должен стать спутником
расширения, а не его урезанной копией:

- быстро понять «где я и что дальше» и одним нажатием продолжить в VS Code;
- поставить или обновить расширение;
- читать условия и теорию с телефона или чужого компьютера;
- видеть прогресс по курсу и статусы защиты понимания.

Наставник в проекте один — владелец. Никаких функций «для наставника», групп, рейтингов
и сравнения студентов на этой странице нет.

## 2. Что есть сейчас

**Маршруты** (`ego_server/main.py`): `/student` и `/student/tasks/{id}` отдают один и тот же
`static/student.html` + `static/student.js` (508 строк, без сборки), `Cache-Control: no-store`.
Каждая отдача пишет в аналитику событие `student_view` (`ego_server/analytics.py`) — сохранить.

**Экраны:**
- вход: логин/пароль (`/auth/login`, регистрация `/auth/register`) и вход через Forgejo
  (`/auth/forgejo/start` → callback шлёт ticket через `BroadcastChannel` → `/auth/forgejo/exchange`);
  токен хранится в `localStorage['ego_student_token']`;
- кабинет: приветствие, сводка (выполнено задач и т.п.), список задач с поиском и фильтрами
  по блоку и статусу, боковая панель задачи (условие в markdown, подсказки до уровня 3),
  блок «Расширение для VS Code» (`/extension/latest`).

**API, которые страница уже вызывает:** `/auth/me`, `/auth/providers`, `/tasks`, `/tasks/{id}`,
`/tasks/{id}/hints?level=3`, `/progress/me`, `/progress/me/understanding`, `/ai/me`, `/extension/latest`.

**Что появилось на сервере и ещё не используется страницей:**
- в `TaskMeta`: `project_id`, `project_name`, `project_order`, `folder_id`, `folder_name`,
  `folder_order`, `theory` (id карточек теории);
- `GET /lessons[?folder_id=]` и `GET /lessons/{id}` — карточки теории (`body_md`; ответы
  «Проверь себя» спрятаны в `<details>`, их **нельзя** вырезать, как вырезают эталон в условиях);
- расширение 0.2.x раз в сутки сообщает свою версию (`X-Cogito-Extension-Version`), сервер
  считает это в аналитике.

**Каталог:** «Python с нуля» — 10 папок, 195 задач, 56 карточек теории; XL-A — 27 задач в одной
папке. Скоро добавится папка-проект «Учёт расходов». Старые 33 задачи (`junior`) выключены.

**Другой вариант кабинета (проверь до начала работы).** В ветке `codex/dashboard-student-tutor`
(коммит `55a7738`) и незакоммиченными в основном чекауте `C:\Work\ego-trainer` лежит более
богатая версия: отдельные страницы задач с вкладками «Условие», «Стартовый код», «Помощник»,
«Защита», файлы `student.css`, `student-navigation.js`, `student-task-page.js`, `student-tutor.js`.
На проде сейчас **не она**, а простая версия из этой ветки. Возьми из неё удачные решения
(навигация, вкладки, черновики), но не выкатывай её целиком без сверки.

## 3. Логика, которая должна совпадать с расширением

Состояния задачи, порядок и «следующая задача» уже реализованы в расширении:
`vscode-ego/src/dashboardLogic.ts` (`taskState`, `pickNextTask`, `compareCatalogOrder`,
естественная сортировка id: `V2 < V10`, `groupCatalog`). В браузере должно получаться
**то же самое**: перенеси логику один в один (JS без сборки) и покрой тем же набором примеров.

Состояния: `new`, `started`, `failed`, `passed`, `defense` (сдано, но защита понимания ещё
не подтверждена; показывать только когда `/ai/me` говорит, что защита обязательна).

## 4. Что сделать

1. **Главный экран после входа.**
   - Приветствие и одна большая кнопка «Продолжить: <задача>» по `pickNextTask`.
   - Рядом «Открыть в VS Code» (см. п. 6) и «Читать условие здесь».
   - Прогресс по папкам курса: «Переменные 13/13», полосы, проекты как разделы.
2. **Курс.** Дерево «проект → папка → карточки теории, потом задачи», как в расширении.
   Статусы задач значками. Поиск по id и названию. Фильтры: «нерешённые», «требуют защиты».
3. **Страница задачи** (`/student/tasks/{id}`, адрес сохранить).
   - Условие; карточки теории из `theory` с ответами в `<details>`; подсказки по уровням.
   - Последняя попытка: статус и сколько тестов прошло.
   - Решения в браузере нет. Есть кнопка «Открыть в VS Code» и, по согласованию, ссылка
     на браузерную IDE `/ide/task/{id}` (она уже существует).
4. **Теория.** Отдельный раздел-библиотека: все карточки по папкам; ссылки
   `task:<id>` и `lesson:<id>` в markdown превращать в ссылки на страницы кабинета.
5. **Расширение.** Блок «Как начать в VS Code»: версия с `/extension/latest`, скачать,
   три шага установки, «обновления придут сами». На главном экране ненавязчиво,
   отдельным разделом подробно.
6. **Глубокая ссылка в VS Code (нужна правка расширения).** Расширение уже регистрирует
   обработчик URI (`vscode-ego/src/forgejoLogin.ts`, сейчас только для входа через Forgejo).
   Нужен второй маршрут, например `vscode://ego-trainer.ego-trainer/open?task=V01`
   (publisher и name из `vscode-ego/package.json`), который вызывает `ego.openTaskById`
   (уже есть). Если расширения нет, ссылка ничего не сделает — рядом нужна подсказка «Нет
   расширения? Скачай».
7. **Защита понимания.** Список «ждут защиты» с понятными статусами
   (`/progress/me/understanding`), кнопка «Защитить в VS Code».
8. **Аккаунт.** Кто вошёл, выход, вход через Forgejo. Регистрация как сейчас.

## 5. Требования

- Без внешних скриптов, шрифтов, CDN и трекеров; без сборщика (как сейчас)
  или с маленькой сборкой, которая кладёт готовые файлы в `ego_server/static/`.
- Стиль — как у лендинга и текущего кабинета: светлая тема, палитра `--ink #172033`,
  `--muted #68738a`, `--line #e5e9f1`, `--canvas #f4f6fb`, `--accent #6558d9`,
  `--green #167a55`, `--amber #946200`, `--rose #b04454`; шрифт Inter/system.
  Бренд и знак — из `ego_server/static/branding/brand.json` (имя остаётся Cogito).
- Тон текста — на «ты», дружелюбно, без канцелярита. Русский язык.
- Адаптив до 360px: телефон — частый сценарий «почитать условие в дороге».
- Доступность: фокус, клавиатура, `aria-*` для фильтров и вкладок, контраст.
- Не ломать: вход (оба способа), адреса `/student` и `/student/tasks/{id}`, событие
  аналитики `student_view`, `Cache-Control: no-store`.
- Шлюз: `/student*` и `/static/*` публичные; API — с JWT. Новые публичные страницы
  не клади под `/admin`, `/tasks`, `/progress`, `/check`, `/run`, `/ai` (там шлюз требует токен).

## 6. Проверки и выкатка

- Тесты: страницы и маршруты (по образцу `tests/test_landing_analytics.py`,
  `tests/test_ide_pages.py`), логика состояний и «следующей задачи» в JS — на тех же примерах,
  что `vscode-ego/src/test/dashboardLogic.test.ts`. Расширение (п. 6):
  `npm run -s compile && npm run -s test:unit && npm run -s smoke` в `vscode-ego/`.
- Посмотреть глазами: десктоп и 375px, вошедший и невошедший студент,
  пустой прогресс и прогресс Егора.
- Выкатка только с согласия владельца. Схема как в прошлых релизах: надстройка над
  текущим образом, кандидат на копии БД и контента, бэкап, переключение, проверка, что
  `students`, `progress`, `runs` не изменились, уборка старых образов.
  Текущий образ на проде — `ego-trainer:release-34aa521`.

## 7. Готово, когда

- После входа за один экран видно: что дальше, прогресс по папкам, как поставить расширение.
- Состояния и «следующая задача» в браузере совпадают с расширением на одних и тех же данных.
- Условие и теория читаются с телефона; ответы «Проверь себя» раскрываются.
- «Открыть в VS Code» открывает задачу в установленном расширении.
- Нет упоминаний наставника, групп и чужих студентов.
- Тесты проходят, вход и старые адреса работают.
